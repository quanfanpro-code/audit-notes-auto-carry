# 🧾 审计附注自动搬运系统

一个在 Word 和 Excel 之间按财务含义搬运附注数据的本地小工具。A端收数、B端供数，两端都可选 Word 或 Excel；结果另存为A端同格式副本并回读核对。文件处理在本机进行；配置外部模型时，识别材料会发送到你填写的服务地址。

---

## 🎯 它到底解决什么问题

做审计报告时，附注里有几十张表：货币资金、应收账款、存货、固定资产……每张表的数字都要从客户给的文件里抄过来。

人工抄有三个麻烦：

1. 慢。几十张表、上千个格子。
2. 容易错。抄串行、抄错列很常见。
3. 改完还得核对一遍，又是一轮。

这个工具干的事就是：分别读取A、B两端 → 认清楚每一格是什么意思 → 在B端找到意思相同的那一格 → 把本次金额和名单写入A端新副本 → 再读实际成品，逐格核对有没有写对。

---

## 👥 谁适合用

- 做审计底稿、每年要把上一年附注改成今年数据的人。
- 手上有一份排版好的上一年 Word 附注，和一份今年的数据表。
- 希望保存原件、逐项核查实际新副本和识别依据的人。

## 🧩 用之前要准备三样东西

| 要准备的东西 | 长什么样 | 说明 |
|---|---|---|
| A端：接收数据的文件 | 一份docx或xlsx，表格已经排好版；Excel可选一张或多张工作表 | 程序只读它，成品另存新副本 |
| B端：提供本次数据的文件 | 一份docx或xlsx；Excel可选一张或多张工作表 | 程序只读它，不改原件 |
| 金标准文件 | 一个后缀为 jsonl 的文本文件，里面是各种附注说法的标准写法 | 随程序放在 `金标准\` 目录里，改它的记录也走版本管理 |

三样东西放在电脑里，通过选择窗口指定；是否发送识别材料取决于你配置的模型服务。A端为Excel时，还需要本机安装可用的Microsoft Excel，由程序在A端副本上写入、重算和保存。

## 🚀 怎么启动

1. 新电脑先安装 Python 3.14；在项目目录安装现有 Python 依赖：`py -3.14 -m pip install -r requirements.txt`。
   - 如果运行的是别人已经编译好的完整程序文件夹，安装 **.NET 10 的 Windows x64 运行时**即可，不需要 SDK。
   - 如果是从 GitHub 下载的源码，先安装 **.NET 10 SDK（Windows x64）**，然后双击 **编译Word桥接.py**。首次编译会联网还原项目依赖，成功后生成 `Word桥接\发布\`；源码、项目文件均在本仓库内，不再需要旧版目录。
   - 微软官方下载：[.NET 10 下载页](https://dotnet.microsoft.com/zh-cn/download/dotnet/10.0)。使用程序选“.NET Runtime / Windows x64”；自行编译选“SDK / Windows x64”。SDK已经包含运行时，不必重复安装。
2. 双击 **启动桌面.pyw**，打开本机桌面工作台。安装上述依赖后还需系统可用的 Microsoft Edge WebView2；普通使用不需要 Node.js。
   - 桌面页面已构建在 desktop_ui 文件夹中，随仓库提供。不要只复制启动文件。
   - 程序使用本机随机端口，不需要记住网址。重复启动会提示回到已有窗口。
   - 使用 Word 文件时需要可运行的 Word 桥接；A 端为 Excel 时需要本机 Microsoft Excel。组件错误在相关任务中显示，不把无关组件作为启动门槛。
3. 仍需旧页面时，双击 **启动服务.pyw**。它与桌面版共用单实例和任务入口，浏览器自动打开实际地址；两个入口不能同时启动。
4. 退出桌面时，未保存的设置或答复先提示；自动任务可安全中断后退出，人工回写需要等待写回结束。程序不会关闭你自己另开的 Excel。

本项目采用**精简发布**，不携带 .NET 运行时。桥接源码和编译入口随 GitHub 仓库提供，二进制不提交；从源码下载后需要编译一次。已编译文件夹可整体移动到其他Windows x64电脑，仍需准备上述Python依赖及.NET 10运行时。

重新编译会先在新的运行子目录构建并检查，成功后才备份和替换原发布文件。备份放在当前用户的 `BackUp\audit-notes-auto-carry_桥接发布_时间\`，逐文件核验SHA256；编译日志在 `运行\桥接编译_时间\编译日志.txt`。编译失败时保留原发布文件。

完整编译参数由Python入口统一维护；自行重新编译也请使用该入口，避免绕过发布备份保护。

## 🖥 桌面工作台怎么用

- **新建任务**：左边选 B（提供本次数据），右边选 A（填写新副本），方向始终是 B → A。Excel 可以勾选一张或多张可见工作表；一次处理同一套报表。金标准、复用等放在“本次设置”中。
- **任务详情**：看真实阶段、错误和下一步。等待答复时可复制材料、粘贴答复，再保存并继续；中断后可回到同一任务继续。查看历史不会切换正在运行的任务。
- **核查结果**：先看任务结论，再选业务表和具体一项。明细分别显示 A 原值、B 本次值、A 最终读值；标题、公式、问题和复用各有页签。可连续看上一项、下一项，也可打开实际副本核对。
- **历史任务**：按文件名和状态查找，返回列表保留筛选。新任务可以指定继续；旧任务没有完整保存原始选项时只读，并提供“用这两份文件新建”，不猜原来的复用设置。
- **识别记录**：平时自动复用。发现错认时查看解释与来源，预览影响后停用或处理冲突；历史任务标记待复核，原报告不会自动重跑或覆盖。
- **设置与人工回写**：设置模型连接、默认文件和字号；人工回写仍使用带连接 Word 与已修改 Excel，另存新副本，不重新识别或配对。

“处理结束”表示程序流程结束，不等于人工审计结论。部分保留、公式待核、回读不一致必须看原因；公式金额相等只代表本次金额一致，不证明公式永远正确。已对应也不等于已写入，页面以最终动作记录为准。

旧任务没有最终动作明细时显示“未记录”，不拿来源金额补成最终金额。文件缺失或被外部修改时会提示；候选副本不会显示为正式成果。结果核查可以复制原样数字和文字，00123、0、空白及未取得会分开显示。

窗口较窄时，详情改为侧边抽屉；Esc 返回原列表。结果支持20、50、100条分页。第一版不做批量排队、手工配对或内嵌 Office 编辑。

## 🔍 后台到底在做什么（按顺序）

1. **📤 提取**：把 Word 里每一张表抠出来，放进一个 Excel 暂存，同时记下每张表前面那句话（标题）、单位和所在章节。
2. **🗂 第一遍：分科目**：整份文件看一遍，只判断「这一段属于哪个科目」。是表、但标准清单里没有对应科目的，写明「无对应科目：原标题」，照抄原文，便于人工一眼认出是哪张表。
3. **📑 第二遍：分表**：在科目里再切一次，判断哪几行是一张表，并给每张表起标准名称。同一张表被分页拆成两截的，要归到同一张业务表里；分不清是续表还是两张同名表的，停下交人工。
4. **🔬 第三遍：逐表精读**：一张表一张表地看，认清哪几列是数据、哪几行是明细、表头有几层、单位是什么，给每个数据格挑标准编号，并标上「同一个编号里排第几」和「这一格是期初、期末还是本期」。
5. **🔗 配对**：两侧先按「科目＋表名」认成同一张表，再按「编号（＋第几项）（＋期间）」一格一格对上。名字不参与判断，它是内容。
6. **📦 搬运**：把B端本次金额和名单一起搬到A端。同一项有失败格则整项保留并列问题。确认同一项目两期均为数值0才不搬，原序号仍占位；真实空白正常配对并清空。B少项且完整性通过才清尾；B多项时先搬容纳部分，超额项目明确列出交人工，不自动加行。
7. **✍️ 写回**：A端为Word时继续用桥接写新副本；A端为Excel时只改允许的位置，纯数字算式按普通金额更新，其他公式保留，由本机Excel重算后与B端对应金额比较。标题只按本次明确位置和日期更新，失败组不混入新数。
8. **🔁 回读**：重新读取实际Word或Excel成品，核对金额、名单、标题和公式。差异、计算错误、没有比较对象或不可比金额都不能报核对通过。

旧任务复用前会重新校验槽位编号和必要期间；失效号或缺失期间会提示新建任务，原结构和答复保留。标题与金额按同一业务表组更新或撤回。Word回读只按既有显示精度处理；Excel公式按实际数值及固定微小尾差比较，文本不去空格、不去换行。

> 为什么中间要绕一圈 Excel？因为 Word 里改数字容易把排版弄坏，先在一份和 Word 表格一一对应的 Excel 上改，再由专门的写回程序一次性写进 Word，安全得多。

## ✋ 「待答复」是什么，遇到怎么办

这里的「三遍识别」既可以自动调模型跑，也可以由人逐份回答。没配模型（或你希望自己看）时，程序会把每一份要看的材料整理好，放在运行目录的 **调用留证** 文件夹里。

你会看到这样的文件夹：

- A_第一遍 —— 整份文件分科目
- A_第二遍 —— 在科目里分表
- A_表001、A_表002 …… —— 每张表一份

每个文件夹里有两个文件：**材料.txt**（要看的内容）和 **指令.txt**（要按什么格式回答）。

桌面版会列出本任务尚待答复的材料。打开一份，复制指令和材料，取得答复后粘贴回来，点**保存答复并继续**。格式错误会保留输入并提示；替换已有答复前需确认，旧答复先备份。

也可以将答案存成材料目录下的 **答复.txt**，再在该任务中点**继续此任务**。旧浏览器页面仍使用“继续上次任务”按钮。

## ⏸ 做到一半断了怎么办

不用从头来。

- 每一份材料答完就落盘，程序会记住做到哪儿。
- 在历史任务里打开原任务，点**继续此任务**，沿用原来那个任务文件夹，从断的地方继续。原文件或规则已变化时会拒绝续跑，应另建任务。
- 旧任务未保存足够的原始选项时，只能查看已有结果；可点“用这两份文件新建”，重新确认本次选择。

## 🛑 哪些情况程序会停下来交给人

程序不猜。碰到下面这些，它会明确报错并把情况写进清单，让你人工处理：

- 某个格子挂不上标准编号（认不出它是什么）。
- 增删的行落在所有表格区域之外，或者横跨两张表。
- 一次改动里既有增行又有删行，或者有两处以上互不相连的增删。
- 列数或列位置变了（本期明确不支持自动加列删列）。
- 表格的合并结构变了。
- 某一格的值读不出来，或者公式没有保存计算结果。
- Excel 多出的项目单列提示人工加行；能容纳的其余项目照常搬运。
- 整表口径对不上：币种、金额单位不一致，或者一边是期末余额、一边是本期发生额。
- 表前日期标题找不到唯一原句，改不了——这张表一个数都不换，避免出现「旧标题配新数」。
- 回读发现差异——步骤会停在「回读不一致」，不会假装完成。

## 📁 跑完之后，运行目录里有什么

每跑一次任务，程序会在 运行 文件夹里新建一个以时间命名的任务文件夹。里面常见这些文件：

| 文件 | 是什么 |
|---|---|
| A、B子目录 | 两端各自的真实提取材料、读取部分进度和调用留证，避免双Word或多工作表互相覆盖 |
| 表A.xlsx、带连接Word.docx、上下文.json | Word路线使用的提取表、位置关联副本和表前上下文；实际路径以接续索引为准 |
| 科目划分_A.jsonl、科目划分_B.jsonl | 第一步的结论：哪些行属于哪个科目 |
| 结构清单.jsonl | 每张表的结构：几列、几行、每行每列是什么角色 |
| A合集.jsonl、B合集.jsonl | 逐格清单：位置、科目、表名、行列路径、标准编号、原值 |
| 对应清单.jsonl | 两侧配对结果与原因 |
| 问题清单.jsonl | 需要人看的格子 |
| 更新后附注表格.xlsx | Word路线换数后的中间表 |
| Word新副本.docx、Excel新副本.xlsx | 按A端格式生成的实际成品；公式待核或部分保留时先看问题清单 |
| 公式核对记录.jsonl | A端Excel保留公式的逐格结果、B金额、差额与结论 |
| 回读记录.jsonl | 实际成品的回读差异；空文件只表示没有发现回读差异，不能替代公式和业务核对 |
| 接续索引.json | 做到哪一步了，断了从这里接 |
| 任务说明.json | 本任务原始选择、执行次数和重复请求凭据，不保存模型密钥 |
| 交付明细.jsonl | 本次实际搬运、保留、标题和最终读值，供界面展示，不参与业务判断 |
| 调用留证 | 每份材料的原件与答复，便于复查 |

## 🔁 跨任务复用（第二份起少调模型）

连续做多份报告时，程序会把第一次认清的表记在本机，下一份先用本次文件核对证据，对得上就不再问模型。同一表换到A/B另一端，或在Word与Excel之间切换，也可以查找既有解释；不是仅凭表名相同就套用。

**哪些会复用。** 第一、二遍按读取部分核对材料类型与整侧布局；第三遍按业务表组核对固定文字、合并、相对位置、名单位置与数量、期间、单位和续表解释。跨格式时前两遍通常重认，第三遍证据完整才可复用。换端、改名、金额变化和名单变化不构成必须重认的理由，但本次坐标、公式、金额、名单、标题、配对和回读全部重新取得。

**哪些一定重来。** 固定文字、表头层级、单位、币种、倍率、合并关系或期间角色不符时，受影响部分回退重认；同一结构有不同解释且未经裁决时不自动选用。标题新文只由本次B端对应期间的实际日期生成，不使用旧任务写回指令。

**记录放在哪。** 默认在项目根下的“识别记录”目录，项目目录允许使用；环境变量“审计附注_识别记录目录”和任务入参可指定其他本地绝对路径。网络共享、映射网络盘及已知同步目录不可用时，只关闭记录读写，本次任务照常完整识别。来源、使用和影响清单会定位到根任务、端、读取部分、工作表和表组。

**怎么关掉复用。** 新建页展开“本次设置”，关闭自动复用；也可在设置页更改今后任务的默认值。原接口仍支持任务输入 `"复用": false`，环境变量 `审计附注_复用=0`（`off`／`false`／`关闭` 同义）仍生效。关闭后继续按原流程识别，历史记录保留不动。

**原生Excel看哪些格。** 两端均有打印区域就取各区域并集，再扣掉隐藏行列；没有打印区域先看所有非隐藏内容。命名表区和本次识别明确的表区内保留空白及合并从属格，不把远处格式或隐藏辅助格扩成大矩形。Word桥接材料不套用这套原生Excel打印规则。

**版本变化怎么办。** 金标准实际内容或识别规则任一变化，旧记录退出自动复用并记明原因。本次证据格式为第5版，旧文件保留；旧任务缺规则摘要或摘要变化时须新建任务。确认某条解释认错了，用本机停用操作登记原因和依据；程序沿来源与使用关系列出受影响任务和工作表，但不会自动重跑历史报告。

**本次证据怎样核对。** 单位必须由识别标明原文位置和适用列，不再搜索第一个“元”或“万元”；来源变化后保存新的证据，后续任务可以复用新记录。写着日期的格子也保留完整原文，只允许日期片段变化，“期初／期末”等其余文字照常核对，不依赖模型额外标注才能保住这些文字。单日期不能借用成立日期、担保期限，期初晚于期末视为矛盾。重认后单位或必要期间仍无法确认，整组金额、名单、合计、清尾和标题保留。续表各自保存自己的行列、例外和口径，不再另存一套主表解释供全组共用。

**哪些记录不会入库。** 每张表要过入库门槛：第三遍没做完、有漏行漏列、缺槽位或未执行的例外、解释越出可见范围，该组就不发布；其他合格组照常入库、照常复用，不会被连坐。停用与登记共用一把跨进程锁，拿锁后重读当前状态：先停用后登记必须被拒，先登记后停用要能列进影响清单。

## 🔐 数据安全须知

- 三份原件全程只读，程序不会改动。测试里有专门一条用例，比对原件前后的指纹。
- 运行目录里装的是真实客户数据，**不要**把这个文件夹提交到网上，也不要用网盘同步。
- 设置区填的密钥用 Windows 自带的加密存本机，不会以明文落盘，也不会在接口里回传。
- **启用外部模型服务时，识别材料会发送到你所填的那个地址。** 发送的内容包括该表的表格原文、表前上下文、以及这张表的候选槽位清单（编号和名称），不包含其他表、也不包含你的密钥以外的配置。
- 程序本身不往任何固定服务器上传数据。除了你自己填的那个地址，没有别的外发通道。不想让数据离开本机，就别填设置区，改用人来答「待答复」。

## 🧪 想确认程序没毛病

项目里的 测试 文件夹是自带的自检用例，覆盖提取、识别、配对、搬运、写回、回读、增删行定位、网页接口。

这些用例由开发人员运行，普通使用不用碰。测试通过仍需核对具体业务场景的真实文件，不能单凭通过数量认定没有缺陷。

开发验证额外需要 `pytest`、`lxml`，安装后运行 `py -3.14 -m pytest 测试 -q -rs`。请先编译桥接；“桥接独立运行”和“桥接真实回归”用例会检查真实exe和docx/xlsx，不会用替身冒充Word集成通过。源码迁入版本及逐文件哈希见 `Word桥接\迁入来源.json`。

## ❓ 常见问题

**双击了没反应？**
多半是没装 Python，或者装的位置不在系统能找到的地方。先确认 Python 能正常用。
另外，双击启动没有黑窗，出了错也看不见。去 运行\启动日志.txt 看最后一行，启动成功会写明实际地址，失败会写明原因；服务自己运行的详细记录在 运行\服务日志.txt，里面会写每次启动、访问和报错。

**网页打不开？**
看 运行\启动日志.txt 里记的实际地址和门牌号。本机端口由程序自动分配，地址以日志里那一行为准。

**选择文件时没弹窗？**
弹窗可能跑到别的窗口后面了，看一下任务栏。

**进度一直不动？**
先看任务详情的真实阶段。未配置模型或需要补答复时，页面显示待答复材料；按提示补齐后继续。连接中断时保留上次状态，不当作任务完成。

**结果里一大堆「仅 A 侧有」「仅 B 侧有」？**
说明两侧没挂到同一个标准编号上。先检查分科目、分表这两步的结论对不对，再看逐表精读里给的编号是不是从候选里挑的。

**数字搬过去变成文本了？**
不该发生。搬运时按原类型写，数字是数字、百分比还是百分比。真遇到就记下来，连同运行目录一起反馈。
