# Word 桥接接口

桥接项目源码已随本仓库提供，可独立编译，不依赖旧版目录。本次完整迁入自 financial-notes-updater 的 c549e5bd92c6d96ad521144724a628228712e4fd；22份文件内容原样保留，哈希见迁入来源.json。复用核心更早来自 audit-notes-tool 的 4856f9dce5fec743f8f0adb4e3ff3f16041f9b75，其原来源.json继续保留。

编译用.NET 10或更新版本SDK，运行用.NET 10 Windows x64运行时。推荐执行仓库根目录“编译Word桥接.py”：精简发布，不携带运行时；先暂存构建，再备份校验已有发布文件。完整步骤见根目录README。启动入口会检查真实桥接，缺运行时则给出中文提示和微软下载入口。

唯一命令行参数为 UTF-8 JSON 请求文件的完整路径。可调用“发布\WordBridge.exe”，也可用本机 dotnet 执行“发布\WordBridge.dll”。标准输出只有一条 JSON；成功退出码为 0，失败为 1，错误格式为 {"ok":false,"error":"具体原因"}。

## 提取

请求字段：action="extract"、word、excel、linked_word、context，四个路径都必须为不同文件。读取 Word 中全部正文表格，调用上游 WordToExcel 创建附注表格和带连接报告，并输出上下文 JSON。任何表不能安全提取则明确失败，不跳过。

成功返回 ok、action、excel、linked_word、context、table_count、warnings。上下文文件 tables 中每表含 table_id、range_name、title、chapter_context（该表前方全部正文段落，排除其他表内文字）、preceding_blocks、unit_text_candidates、context_note、sheet、first_row、first_column、row_count、column_count、source、link_error、structural_omissions。首行、首列从 1 开始。

preceding_blocks 按实际先后顺序记录 paragraph（text）和已经过的 table（table_id），保留局部说明与原表的先后关系。unit_text_candidates 保存前文出现“单位”的候选段落，不指定当前表的单位；适用性由原文语义判断。context_note 明确这层区别：行列范围只关联原文，不证明所有前文都适用。2026年09月21日起新提取不再输出含糊的 unit_text 字段；已有位置关联与识别成果保持原样，不替换历史依据。

structural_omissions 保存 Word 原表没有单元格的结构空位，每项含 sheet、range、reason；无此空位时为空列表。它与真实存在但金额为空的单元格不同，不能进入语义映射或业务补格。例如行首省略一列样例中 sheet1!B3 不存在对应 Word 格，第二行首个实际格为 C3。

## 读取

请求字段：action="read"、word。返回 ok、action、word、source_hash、tables。tables 字段同上。无连接时区域和来源字段可能为空。

## 更新

请求字段：action="update"、word（带连接报告）、excel（更新后附注表格）、output、operations（可为空数组）。

输出不能与任何输入相同。已有结果写入前先备份到用户 BackUp 目录并比较哈希。原 Word、原附注表格及更新后附注表格均不修改。更新前校验全部来源，任意一张表不能更新则不发布最终报告。完成后重新读取 Word 检查全部表内容。

operations 按数组顺序执行：

```json
{
  "range_name": "TA_001",
  "axis": "row",
  "action": "insert",
  "index": 3,
  "count": 1,
  "template_index": 2
}
```

axis 为 row 或 column；action 为 insert 或 delete；index 是相对于该命名区域的第 0 个起始网格位置。insert 在 index 前插入，index 等于总数量时追加；template_index 为变更前复制样式的行或列，insert 时必填。delete 从 index 开始删除 count 个完整行或列。所有位置基于执行该项操作前的当前表结构，与更新后附注表格的 Excel 结构处理顺序必须一致。

增行复制指定行的单元格、段落和字体样式，清空原值；增列复制指定列的样式与列宽并更新 Word 网格。原有行列格式保留。不能删除整张表；不通过行列差额推测变更。

合并处理：允许不切开现有合并块的操作；切入横向或纵向合并块、复制跨合并的样式来源、存在整行纵向续接或行首省略网格时，会说明具体原因并停止。复杂表的普通数值更新复用上游合并算法；带行首省略的新提取连接额外按网格边界定位。旧连接保留原有编号规则。省略位置填写值、公式或被 Excel 合并范围跨越时会明确拒绝；不会静默丢弃数据或补造 Word 格。

成功返回 ok、action、output、successful_tables、written_cells、output_verified、errors。written_cells 是上游回刷的全部表格单元格数，不等于数值发生变化的单元格数。

中间文件保留在结果文件同目录的 Word桥接中间文件_GUID 中，以便核查和恢复，不自动删除。

## 验证

update可带caption_updates数组，每项为range_name、old_text、text。仅更新所属表前、上一张表之后原文唯一匹配的普通文字标题；同名其他表标题保持。原文不存在、不唯一或包含域、链接等复杂对象时拒绝发布。保留段落与字体属性，结构保存和最终输出都回读标题。语义更新入口从已核准的Excel标题文字清单生成此安排，不按全篇同名文字替换。

本仓库“测试/test_真实桥接集成.py”“测试/test_桥接真实回归.py”使用真实docx/xlsx及编译后的桥接，覆盖提取、内容写回和回读、标题及粗体保留、增删行、跨合并拒绝、行首省略格定位与冲突拒绝、原件哈希不变。“测试/test_桥接独立运行.py”验证缺运行时指引、启动前检查及编译失败保护。更早上游测试的增删列等能力描述不等于本轮全部复验；结果以本仓库实际测试记录为准。每轮使用新的测试目录，不覆盖旧测试文件。
