# 需求补遗：配对口径、名称搬运与结构变动边界

日期：2026-11-02
适用对象：审计附注自动搬运系统
关系：本文件是 `2026-11-01-审计附注自动搬运系统-requirement.md` 的补充，不替代原文；两份冲突时以本文件为准，并同步修订设计与计划。

## 一、为什么要补这一份

第五阶段复核（2026-11-02）提出 18 条问题，其中三条不是代码没照计划做，而是计划的写法本身错了：

1. 计划写“配对键只有一个：槽位编号”，导致一个编号覆盖多行时无法区分，也把币种等口径信息一起丢掉。
2. 计划写“跳过行名列”，把公司名、项目名这类本来就该搬的内容整列排除。
3. 计划写“列调整本期不做”，但实现对列变化静默放行，既不报错也不提示。

经与用户逐条确认，把这三条的口径重定，连同复核中确认为缺陷的其余问题，一并写入本补遗。

## 二、概念先定死

| 名词 | 含义 | 说明 |
|---|---|---|
| 槽位 | 科目、表、行路径、列路径共同确定的一个“格的类型” | 编号是它的名字，如 C-N054-T003-S002 |
| 维度 | 金标准为这个槽位声明的限定条件 | 固定四项：期间、币种、金额倍率、单位；另有披露项目、账龄区间、对方单位、被投资单位、项目等五十余种，按科目而定 |
| 维度值 | 这一次实际填的值 | 例：期间＝期末，币种＝人民币，披露项目＝债券乙 |
| 序号 | 同一个编号在这张表里排第几：1、2、3…… | **由识别给**。固定项只有一个，序号空着；名单项按出现先后编号。识别失败的格子也给序号，只是编号空着 |
| 业务表组 | 一张业务表加上分页拆出的续表 | 计数、配对都在组内进行；归属不明交人工 |
| 汇总格 | 合计与小计 | 不占序号、不计入清尾，但照常搬，取 B 原值 |
| 项标签 | 名单项的抬头文字：排在行上是行标，排在列上是列标题 | 是内容，跟数字一起从 B 搬；固定项和汇总项的标签是身份，不搬 |

要点：一个编号只说明“这是哪一种格”，不说明“是第几个”。同一个编号可能对应好几个项（好几只债券、好几个类别），靠序号区分。序号只表示先后，不涉及方向——排在行上还是列上，程序不问。

## 三、配对与搬运口径（本轮核心变更）

### 3.1 配对

先说清楚“按哪张表配对”。Word 因为分页，常把一张业务表拆成两张物理表（续表）。计数和编号之前，必须先确认哪些物理表属于同一张业务表、哪张是续表；归属不明的交人工，不凭表名相同就合并。

**两侧靠什么认成同一张表。** A 侧的表在 Word 里叫 TA_008，B 侧的表在 Excel 里叫「word附注!120」，这两个号永远不可能相等。所以配对用的业务表键统一取**科目＋表名**（续表并入同一个键）。同侧出现两个完全同名的业务表时，无法确认哪张对哪张，该科目交人工，不按位置猜。

**配对看三样：编号＋序号＋期间角色。**

- **序号**是“同一个编号在这张表里排第几”，由第三遍识别给。固定项只有一项，序号留空（一项里可能有两格，比如期初和期末，靠期间角色分）；名单项（甲债券、薪酬类别、资产类别）按出现先后给 1、2、3。
- **期间角色**是这一格在项内属于哪个期间，同样由识别给，统一按下面七个写法之一填写：

| 期间角色 | 什么时候用 |
|---|---|
| 本期期初／本期期末 | 表里同时有本期和上期两套期初期末时 |
| 上期期初／上期期末 | 同上，指上期那一套 |
| 本期发生／上期发生 | 发生额类，同样区分本期和上期 |
| 未知 | 原文确实看不出，或识别没把握 |

**表里只有一套期初／期末时，一律记“本期”。** 附注里绝大多数表只列一组期初、期末，那就是本期的，记成“本期期初／本期期末”，不要写裸的“期初”“期末”。这样两侧写法统一，不会因为一边写得短、一边写得长就配不上。

为什么要第三样：同一个编号可能同时管住一项的好几格。真实金标准里：

- 「应付职工薪酬分类余额」（C-N049-T001-S001）列路径只写“余额”，来源记录里既有期初也有期末；
- 「库存现金余额」（C-N087-T001-S001）来源里同时有“期末余额”和“期初余额”；
- 「现金等价物余额」（C-N067-T001-S317）更极端，同一编号盖住四格：本期期初、本期期末、上期期初、上期期末；
- 「委托代销手续费」（C-N095-T001-S103）同一编号同时用于本期发生额和上期发生额。

只按“编号＋序号”配，这些格会撞成同一个键，分不开；按出现顺序硬配，两侧排列相反时还会把期末搬进期初格。

**期间实际年份不参与。** 2024 年期末配 2025 年期末是正常换年，必须照常更新；参与比较的只有上面那个角色写法。

**“未知”不能当相同期间的证据。** 两侧都写“未知”，只说明两边都没看清。**“两边各只有一格”也不构成证据**——唯一那一格同样可能是期初或期末，认错了就是把期末数写进期初格。

处理看这个编号在金标准里要不要期间。**要不要期间，由金标准里这个编号有没有 `period` 维度决定，一个编号一个结论。**

| 该编号 | 实证条数 | 配对条件里有没有期间角色 |
|---|---|---|
| 声明 `period` 必填 | 11,395 | **有**。每格必须给明确期间角色；任一侧是“未知”就不配、记问题、整项保留 |
| 没有 `period` 维度 | 1,422（文字类 585、金额类 660、其他 177） | **没有**。期间完全不进配对条件，只按编号（固定项）或编号＋序号（名单项）配 |

程序直接读金标准判断，不靠“有没有第二个候选”来猜。`period` 必填的例子：`C-N087-T001-S001`（库存现金余额）的 `period.required` 为真，同一来源表里既有期初也有期末，光凭编号分不出是哪一期。

没有 `period` 的例子：`C-N019-T013-S006`（其他应付款／按交易对手方归集的期末余额前五名的其他应付款情况／`<单位全称>` ／款项的性质），`dimensions` 只有 `counterparty`，没有 `period`。这是有自己编号的普通文字格，不是不参与配对的项标签。它的期间**不该参与比较**：A 写了“本期期末”、B 写“未知”，仍然要配上，把 B 的文字搬过来。

**“周期不同配不上”这条只管要求期间的编号。** 不要求期间的编号，两侧写了不同的已知期间也照样配——那些期间值仍然照实保存在记录里，只是不参与比较，不许为了“不参与比较”去改写或删掉原识别结果。

| 情况 | 怎么配 |
|---|---|
| 要求期间·序号空（固定项） | 编号相同、期间角色相同，才是同一格；两侧顺序不同也能对上 |
| 要求期间·序号有值（名单项） | 编号、序号、期间角色三样都相同，才是同一格 |
| **不要求期间**·序号空 | 只按编号，期间不看 |
| **不要求期间**·序号有值 | 按编号＋序号，期间不看 |
| 不要求期间·汇总格 | 按编号＋分组，期间不看 |
| 同一张表里名单在行和列上都有 | 交人工，程序不猜 |
| **同一组完整配对键**下同侧不止一格 | 该表判失败交人工，不按顺序硬配。不要求期间的编号，判断重复时也不看期间 |
| 期间角色为“未知”且该编号要求期间 | 不配，记问题，整项保留 |

**同一侧出现多个编号、序号都空，是正常情况。** 货币资金表里库存现金、银行存款各是一个固定项，编号不同、序号都空，照编号各配各的，不能判成重复。

**为什么不让程序自己判是不是名单。** 程序能看到的只有“这个编号出现几次”，次数说明不了性质。真实金标准里两类反例正好相反：

- “应付职工薪酬分类余额”（C-N049-T001-S001）槽位名**没有**尖括号，行路径却是 `<薪酬类别或类别集合>`，两个薪酬类别合法共用一个编号。按名字判会当成固定项，把正常数据判成重复。
- “债权投资／债权投资的情况”（C-N014-T001-S001…S006）整表**没有文字槽位**，行路径却是 `<披露项目>`。按“有没有文字槽位”判，债券名会被当成标签，搬出“甲债券的名字＋乙债券的金额”。

所以“这一项是不是名单项、排第几、这一格是期初还是期末”都由识别给，程序只执行。尖括号、维度声明只是识别时的线索，不是判据。

三条边界（下文说的“名单”，就是指有序号的那一组）：

- **名单只剩 1 项、甚至这一期 0 项，仍然是名单**，照样走名单规则。
- **同一个编号、同一个序号、同一个期间角色，在同一侧出现两格以上** → 该表判失败交人工，不自动改判。注意限定词：是“同一组完整配对键下多格”，不是“序号空着就不能有多个编号”。不要求期间的编号，判断重复时也不看期间，只看编号（和序号）。
- 名单这一期 0 项，必须是识别结果**明确写了“本期无”**，并且完整性前提成立。没识别、读取失败、没找到对应业务表，都不能当成 0 项。

名称不参与判断。编号是否合法，按金标准里真实存在的编号判断，不限定 C 开头，P 类同样有效。

### 3.2 搬运

- **整项同进同退**：一个名单项（一行或一列）里，凡是要搬的格（项标签、各数据格），任何一格缺编号、未对应或读值失败，这一整项保留原样并列问题。不允许“名字换了、数没换”，也不允许把不同 B 项拼成一行。真实空白不算失败。
- **项标签搬不搬**：
  - 名单项：标签是内容，随项从 B 搬。排在行上的写回行标，排在列上的写回列标题。
  - 固定项、汇总项：标签是身份，**不搬**，原样保留。
- 数据格的值全部从 B 取：金额、币种、期间、其他维度，一起绑上去写回。A 里的旧值只作为改前原样留痕。
- 合计、小计取 B 的原值，程序不自行重算。
- B 有值就搬值；B 是空就清空；B 读不出来就整项不动，列问题。
- 项数按下面三条处理，**只对名单适用**。判断项数，看两侧**完整项清单的项数**（含识别失败的占位项），不看某个编号桶里有没有 A 的记录：
  1. **项数相同**：第 N 项对第 N 项，逐项覆盖。
  2. **B 少于 A**：前若干项逐项覆盖；A 尾部多出来的项整项清空，标签与数据都不留，并在问题清单里注明“B 无此项，已清空，请人工确认是否删行或删列”。表的结构不变。B 是 0 项（明确写了“本期无”）也算这一种：A 的名单项全部清空。
  3. **B 多于 A**：A 装不下，整表停止，交人工增行或增列，程序不自动加。

  **A 里某一格没认出编号，不是“A 少了一项”。** 项还在、序号还在，只是那一格配不上。处理是：该格未对应 → 这一整项保留原样并列问题，同表其他项照常搬。绝不因为某个编号桶里查不到 A 的记录就判“B 有 A 无、需要加项”，否则一格的识别失败会把整张表停掉。
- **固定项不做清尾**：B 里没有某个固定项（比如今年没列库存现金），保留 A 的原值并列问题，不当成“B 无此项”去清空。
- **清尾前必须证明 B 完整**，四条同时成立：
  1. 第一遍的划分覆盖全部有内容行，没有未解释的空档；
  2. 第二遍把每一段都归到了表或明确标为非表格，没有漏段；
  3. 第三遍的清单覆盖本组全部项，识别失败的项也占位、也计入项数；
  4. 名单本期 0 项时，识别结果显式写了“本期无”。

  **第三遍的四项校验通过，不等于 B 完整**——它只证明交上来的部分自洽，证明不了漏掉的那几项不存在。四条不成立就不清尾，列出具体范围问题。

### 3.3 项标签就是名称，不再另设“名称格”

名称不是一个单独的格子，而是名单项的抬头：排在行上是行标，排在列上是列标题。它跟数字一起构成这一项的内容。

| 项的情况 | 例子 | 标签怎么处理 |
|---|---|---|
| 名单项 | 甲债券、薪酬类别、资产类别（列标题） | 是内容，随项从 B 搬 |
| 固定项 | 库存现金、银行存款 | 是身份，原样保留，只更新金额 |
| 汇总项 | 合计、小计 | 不搬 |

这样做的好处：

- **不需要给名称单独配槽位编号**，也就不存在“名称编号给不出、整项被卡住”的老问题；
- **不会出现“甲债券的名字＋乙债券的金额”**，也不会出现“运输工具的列标题＋专用设备的数”——标签和数字同批取自 B 的同一项；
- **库存现金的金额不会被标签拖住**，因为固定项的标签压根不参与搬运。

补充两条：

- 项标签以外的文字列（比如“与本企业关系”这种另有编号的文字列），按普通数据格处理，靠编号＋序号＋期间角色配对、随项走。
- 某个文字列在金标准里查不到编号：该格记“编号缺失”，整项不搬并列问题。**不许因为查不到编号就把它当固定标签糊过去。**

### 3.4 什么时候整表停下交人工

- B 的项数多于 A：A 装不下，需人工加行或加列。
- **币种或金额单位不同**：例如 A 是人民币元、B 是人民币万元或美元，数字口径不一样，整表停。
- **期间口径不兼容**：期间角色或跨度根本不同（例如 A 是期末余额、B 是本期发生额），整表停。
- 业务表归属不明：分清不了哪几张物理表是同一张业务表、哪张是续表。
- 同一表内出现程序无法判定的重复或空缺。

**正常的换年不算冲突**：A 写“期末指2024年12月31日”、B 写“期末指2025年12月31日”，两边都是期末余额，属于同类期间换年，应当采用 B 的日期，不能因为两句话不一样就停。判断依据由识别结果给出（期间角色、跨度是否相容），程序不靠比较两段文字。

**日期标题改不了时，这张表不换数**：需要改表前日期标题、但段落无法唯一定位时，该表保持原样并列问题，其他表继续。不允许出现“2024年的标题＋2025年的数”。

## 五、明确不做

- 列调整（自动增列删列）：本期不做。检测到列数或列位置变化时，明确报“列结构变化，本期不支持，交人工”，不得静默放行。
- 名单项数比 A 多（不论多一行还是多一列）：本期不自动加，整表停、交人工。
- 不新增依赖，不新增数据库，不更换 Word 读写链路，不引入前端框架。
- 不做与上述 18 条无关的重构。

## 六、约束

- 走完整六阶段：需求补遗 → 设计修订 → 计划修订 → 编码 → 审查 → 交付。
- 每条修复先写能复现的失败用例，再改代码；改完跑全量并贴结果。
- 三份原件（Word、数据表、金标准）只读，测试须断言原件未被改动。
- 修改已有文件前先备份并校验。
- 识别仍为三遍线性，不并发。

## 七、验收标准

在原有九项之外，增加以下可判定条款：

| 条款 | 判定方法 |
|---|---|
| 固定编号按编号对应，顺序不同也能配 | 库存现金、银行存款两侧顺序相反，断言各自更新到正确项目，不得判未对应，也不得清空 B 仍有的项目 |
| 固定项标签不搬、金额照更新 | 库存现金 A 写 100、B 写 110，断言金额变 110，行标仍是 A 的“库存现金”，不因查不到名称编号停下 |
| 名单项标签随项搬（真实债权投资） | 用 C-N014-T001-S001 等 6 条真实槽位：A 第一行“甲债券 100”、B 第一行“乙债券 200”，断言整行变成“乙债券 200”，绝不出现“甲债券 200” |
| 名单项按序号配 | 同一编号两行、内容不同，断言序号 1 对 1、2 对 2，不串行 |
| 同一项的期初期末分得开（真实薪酬） | 用 C-N049-T001-S001：某一项同时有本期期初 100 和本期期末 120，B 为 200 和 220，断言两格各对各的，不重复、不串期 |
| 期初期末排列相反也不串（真实固定资产） | 用 C-N038-T001-S001：同一类别同时有期初、期末，A、B 两列顺序相反，断言仍按期间角色配上，标签与整项数据一起更新 |
| 两侧表组标识不同也能对上 | A 的表叫 TA_008、B 的表叫 word附注!120，识别确认是同一张业务表后，断言正常配对搬运；同科目两张独立同名表仍交人工 |
| A 某格缺编号不误判加项 | A、B 各两项，A 第 1 项某个金额格缺编号：断言第 1 项保留并列问题，第 2 项照常更新，不报“需要加项”、不停整表 |
| 名单不由槽位名或出现次数推断（真实薪酬） | 用 C-N049-T001-S001：槽位名无尖括号、行路径为 `<薪酬类别或类别集合>`，给序号 1、2 后两个类别正常配，不得判“固定项重复” |
| 两套期初期末也分得开（真实现金等价物） | 用 C-N067-T001-S317：同一编号盖住本期期初、本期期末、上期期初、上期期末四格，A、B 排列不同，断言四格各对各的，不撞号；换年度照常更新 |
| 两个“未知”不得配成一对 | 同一编号在一项里有两格，A 本期期初标“未知”100、本期期末标“本期期末”120；B 本期期初标“本期期初”200、本期期末标“未知”220；断言 A 本期期初不会被 B 本期期末的 220 覆盖，受影响格进问题清单，整项保留 |
| 唯一一格未知也不配 | 用 C-N087-T001-S001：两侧各只有一格、期间都标“未知”，A 实际是期初 100、B 实际是期末 220；断言不判对应、不写入，问题清单记“期间未确认” |
| 不需要期间的编号不受影响 | 取一条没有 period 维度的名称类槽位（如 C-N054-T003-S002），期间未知照常配对，证明这条限制没有扩大到所有槽位 |
| 不需要期间的编号，期间不同也照配（真实款项性质） | 用 C-N019-T013-S006（其他应付款，dimensions 只有 counterparty）：同编号同序号，A 写“本期期末”往来款、B 写“未知”保证金，断言仍判对应并把 B 的文字搬过来；两侧写两个不同的已知期间，同样照配；原期间值在记录里保留未被改写 |
| 不需要期间的编号，重复判断不看期间 | 同侧两个 C-N019-T013-S006，期间角色一个“本期期末”、一个“本期期初”，其余条件相同 → 判重复交人工，不能因为期间写法不同就逃过重复检查 |
| 同一配对键下多格才判失败 | 同一编号、同一序号、同一期间角色在同一侧出现两格 → 该表失败交人工；库存现金、银行存款两个不同编号各一格 → 正常对应，不判重复 |
| 列上的名单同样能搬（真实固定资产） | 用 C-N038-T001-S001（列路径 `<资产类别>`）：A 三列“房屋／机器／运输”，B 三列“专用设备／房屋／运输”，断言三列按序号整体替换，列标题与数字一起换，绝不出现“运输工具的标题＋专用设备的数” |
| 名单只有 1 项仍是名单 | A 名单 1 项、B 明确写“本期无”且完整性成立，断言该项被清空并记录；B 未找到或识别失败则不清空、列问题 |
| 失败格占位不前移 | B 第 1 行金额缺编号、第 2 行完整；断言 A 第 1 行保留原样，A 第 2 行按 B 第 2 行更新，绝不出现“丙＋B 第 2 行的金额” |
| 清尾前须证明 B 完整 | B 实际 3 项、前两遍只圈 2 项；断言不清 A 第 3 项，并列出范围问题 |
| 合计取 B 原值 | A 明细 100＋200、合计 300；B 明细 400＋500、合计 900；断言合计写成 900，程序不自行相加 |
| 多个小计不串组 | 两个分组各有小计，断言各取各组的 B 值 |
| 续表合并后计数 | A 分成两张续表、B 合成一张，两侧各 4 项，断言正常处理；两张独立同名表不得混配 |
| 项标签与数据同组更新 | 标签成功、金额失败；金额成功、标签失败。两种都断言整项保留原样并列问题，不出现新旧混搭 |
| P 类编号可用 | 用真实 P 类编号构造用例，断言判为“对应”而非“缺失” |
| 别名进入材料 | 提供带别名的候选，断言别名出现在实际送出的第三遍材料里 |
| B 少于 A 时尾部清空 | 构造 A 三项、B 两项，断言前两项按 B 覆盖，第三项标签与金额均为空，问题清单有“已清空”记录 |
| B 多于 A 时整表停 | 构造 A 两项、B 三项，断言不产生任何变更并列出原因；多一列同样停 |
| 正常换年可更新 | A 写 2024-12-31、B 写 2025-12-31，同为期末，断言按 B 更新，不判冲突 |
| 期间口径真冲突才停 | A 是期末余额、B 是本期发生额，断言整表停 |
| 标题改不了则整表不换数 | 标题无法唯一定位，断言该表数字未被更换，问题清单有记录 |
| 币种或单位不同整表停 | 构造人民币元对人民币万元，断言整表交人工 |
| 口径句不含关键词也要进材料 | 表前句为“以下金额均以人民币万元列示”，断言该句进入材料，且万元与元被识别为口径差异 |
| 范围越界必失败 | 模型给出本表之外的坐标，断言该遍失败而不是照收 |
| 回读差异必失败 | 构造差异，断言步骤不是完成且差异可查 |
| 列变化明确拒绝 | 构造加列，断言报“不支持”，不得返回空操作 |
| 接续不新建目录 | 中断后再次开始，断言沿用原目录、不重跑已完成 |
| 人工成果不被覆盖 | 已有更新表被人工修改后再接续，断言原文件未被自动重生成覆盖 |

## 八、待确认项

无。已确认的口径：

- 配对看**编号＋序号＋期间角色**；序号、期间角色都由识别给，不是名单、排第几、哪个期间都不靠程序推断。
- **期间角色只在金标准要求期间时才进配对条件**：该编号没有 `period` 维度，就只按编号（固定项）或编号＋序号（名单项）配，期间写了不同的值也不影响；原值照实保留，不改写、不删除。
- 期间角色统一七种写法：本期期初、本期期末、上期期初、上期期末、本期发生、上期发生、未知；表里只有一套期初／期末时记“本期”。
- 期间实际年份不参与，正常换年照常更新。
- **“未知”不能当相同期间的证据**：该编号声明 period 必填时，未知就不配、记问题、整项保留；没有 period 维度的编号不受影响。两侧各只有一格也不例外。
- 同一侧多个编号、序号都空是正常的（库存现金、银行存款），只有“同一完整配对键下多格”才判失败。
- 两侧用**科目＋表名**认成同一张业务表，因为 A、B 各自的表号不可能相等；同侧同名多张交人工。
- 名单项的标签（行标或列标题）是内容，跟数字一起从 B 搬；固定项和汇总项的标签不动。
- 项数比 A 多就停，比 A 少就尾部清空；判断项数看完整项清单，不看某个编号桶。
- 列调整（自动增列删列）本期不做。

另有一条要实测：**列标题可能落在合并单元格里**，桥接能不能写进去尚未验证，将用一条集成用例专门验；写不进去时该表退回人工（标签与数字都保持原样），其他表照常。
