## 三、三处自主判断及依据

**一、末尾删行与“把最后一行清空”在文件层面难以区分。**
判据：该行位置已被后面的行顶上（有值）→ 真删行；该行连样式都没了 → 真删行；该行还在、只是没内容 → 当作清空，不生成删行操作。
理由：把“清空”误判成“删行”会真的从 Word 里删掉一行，损失更大。宁可留着让人定。

**二、项标签不参与按编号配对。**
项标签在清单里状态记为“不参与”、原因“项标签”，不混进“槽位编号缺失”。它跟随所在项搬运，取 B 同项的文字。
理由：项标签本身没有编号，若按缺失统计会淹没真正的问题。

**三、整组判不了时，项标签仍进清单。**
口径冲突、需加项、整表缺失这三种整组失败，项标签记“不参与”，其余格记失败原因。
理由：计划要求“未对应的每一格都要进清单”，项标签也是格，不能凭空消失。

## 四、未覆盖的一项

**⑬ 往合并的列标题写文字**：现有测试样本没有多级合并表头，无法在单元测试里构造真实 Word 结构。这一项留到天宇油脂验收时用真实附注验证；写不进去时该表退回人工，其他表不受影响。已写入 `docs/验收准备.md` 的待验证清单。

## 八、两份专项参考的抽检结果

`code-reviewer` 附带的 `python.md` 与 `fastapi.md` 是示例集而非打勾表，按类别抽检如下。

| 类别 | 本项目情况 | 结论 |
|---|---|---|
| 类型注解 | 核心函数大多有注解；少量内部辅助函数与测试没有 | 接受：本地工具、无外部调用者，不为此返工 |
| 资源管理 | `保存更新表`、`回读验证` 都用 finally 关闭工作簿；测试里曾因句柄未关导致 Windows 文件锁，已改成读完即关 | 已修 |
| 异步 | 接口用同步 def，由 FastAPI 放线程池；长任务用后台线程加轮询 | 接受：单用户本地工具，异步化属过度设计 |
| 请求模型 | 用 `请求: dict` 而非 Pydantic 模型 | 接受：只服务本机页面，无外部调用者；现在引入模型层没有收益 |
| 依赖注入 | 无依赖；配置路径与运行状态挂在 `应用.state` | 接受：单例应用，无测试替身需求 |
| 错误处理 | 接口失败返回 `ok:false` 或 HTTPException；任务线程异常写进日志 | 接受 |
| 安全 | 只监听 127.0.0.1；密钥 DPAPI 加密落盘、不回传明文 | 符合 |

抽检中看到但本轮不改的一项：**桥接子进程调用没有超时**。桥接若卡住，任务线程会一直等，界面只显示步骤不变。加超时需要真实大文档的耗时数据（天宇验收时记录），现在拍一个数值有误杀长任务的风险，因此列入下一轮。

## 九、遗留风险

- 合并列标题写入未验证（见第四节）。
- 两侧模型给的表名若不一致，会分成两组、全部未对应；不会错搬，但会白跑。验收时观察。
- 项标签取 B 同项文字依赖 `科目＋表名＋行号` 对得上；对不上时该项标签不写，整项数据仍照常搬。
