## 一、方案比较

三个可行方案（都遵守“新建干净项目、旧代码按需抄用”）：

**方案A — 文件流水线＋轻Web服务**：核心流水线是一组纯 Python 模块，输入输出全是文件；FastAPI 服务只负责页面、触发和查询；每次任务一个运行目录，产物按需求约定落盘。

**方案B — 任务数据库为中心**：格子、身份证、对应关系存 SQLite，文件只作导入导出。

**方案C — 命令行核心＋WebUI只读展示**：流水线命令行跑，Web 只看结果。

| 比较项 | A 文件流水线 | B 数据库中心 | C 命令行＋只读展示 |
|---|---|---|---|
| 实现成本 | 低 | 中高（另做导出层） | 低 |
| 维护成本 | 低（产物即证据） | 中（库与文件两套备份保护） | 低 |
| 风险 | 低 | 与现有成果形态、备份哈希及接续约定不一致 | 验收体验差，不满足需求第8条 |
| 旧代码兼容 | 高（合集/回执格式可抄） | 低 | 高 |
| 测试难度 | 低（文件进出可断言） | 中（测试要起库） | 低 |
| 可逆性 | 高 | 低 | 高 |

**结论：采用方案A。** 需求约定的权威产物本身就是文件（合集、对应清单、回读记录、接续索引、备份），文件形态天然构成验收证据；选文件是因为贴合现有成果形态与验收约定、改动更少，并非数据库做不到备份（SQLite 有官方备份机制，详见 ADR-0001），B 的查询优势在单机单用户规模下用不上；C 无法在浏览器里触发任务和人工回写，不满足需求。前端选无构建链的原生 HTML/CSS/JS（就四个页面，不做前端工具链，换前端框架不影响核心）。

## 二、推荐方案设计

### 2.1 目录与模块

```
C:\Users\27651\Documents\Code\审计附注自动搬运系统\
├─ 核心\            流水线包（中文模块名）
│   提取.py 识别.py 比对.py 搬运.py 写回.py 回读.py
│   接续.py 模型调用.py 表格.py 表格文字.py 设置.py
├─ 服务\            web.py（FastAPI）＋ 页面（HTML/CSS/JS）
├─ Word桥接\        复制旧编译产物＋接口说明（只进不出）
├─ 测试\            pytest 用例
├─ 运行\            每次任务一个运行目录（产物全在这）
└─ docs\            requirements / specs / plans / reviews / adr
```

进程模型：Web 服务单进程；流水线在后台线程执行，同一时间一个任务（单机单用户）；前端 2 秒轮询进度接口；任务可请求中断（模型调用前检查取消）。

### 2.2 数据流（运行目录产物）

输入（只读：Word 原件、统计 Excel、金标准、模型配置）→

1. 提取 → `表A.xlsx` ＋ `带连接Word.docx`（桥接的带连接报告，回写的必需输入）＋ `上下文.json`（表位置与前后原文）
2. 识别 → `A合集.jsonl` ＋ `B合集.jsonl` ＋ `调用留证\{序号}\`（请求/响应原文）
3. 比对 → `对应清单.jsonl`（含未对应项及原因）
4. 搬运 → `A′数据.xlsx`（即 Excel 新副本：已对应格＝B 原值，未对应格原样）
5. 写回（update 输入：`带连接Word.docx` ＋ 按真实路径重新读取的、用户实际保存的 A′）→ `Word新副本.docx` ＋ `回读记录.jsonl`

全程 → `接续索引.json`（登记中间产物，带连接Word 在内）；改前备份到 `C:\Users\27651\BackUp\`（哈希校验）。原件全程只读。

### 2.3 WebUI（4页）

- **任务页**：选 Word / 统计 Excel / 金标准——点按钮由本机程序弹出 Windows 选择窗口，记录真实文件路径（浏览器文件框拿不到本机路径，不用）；启动、进度、中断。
- **结果页**：对应清单、未对应问题清单（可筛选）、回读结果、打开产物。
- **设置页**：API 地址、API 密钥、模型名、超时；连通性测试按钮。
- **人工回写页**：选更新后 Excel（同样弹 Windows 窗口记真实路径）、一键打开 Excel 人工编辑、触发回写 Word——回写时按真实路径重新读取你已保存的那份 Excel，不读选择时的旧内容；展示结果。

视觉：中文界面，浅色工作台风格，表格/进度/状态配色清晰易读。

### 2.4 模型调用

- 识别通道双轨：①运行期可选用户配置的 HTTP API（OpenAI 兼容格式 `chat/completions`；密钥存本地配置文件，默认 Windows DPAPI 加密，不进日志）——**暂不配置**；②开发与验收期走"委托识别＋答复导入"：材料与指令照常组装并留证，由 WorkBuddy 子 Agent（DeepSeek V4.1 Flash 1017）产出答复，程序按既有答复导入，断点复用照旧（详见 ADR-0003）。
- 提示词组装：简短指令（问法）≤2000 字符，程序硬校验、超限拒发；必要表格文字、完整上下文和相关金标准完整提供，不受 2000 字限制，不得为过字数检查删减识别依据。材料仍只留必要部分，不夹带无关合集、不重复展示。
- 每次调用留证：`调用留证\{序号}\` 下请求、响应、耗时。
- 失败/超时：该范围标记“识别失败”进问题清单，不自动重试、不硬凑；重新识别由人工触发。

### 2.5 Word 桥接复用

- 复制旧项目 `Word桥接\发布\` 全部编译产物＋`接口说明.md`；子进程＋UTF-8 JSON 请求文件调用（extract / read / update）。extract 产物含带连接 Word 副本，update 以其为输入之一，登记进接续索引。
- 期间标题更新走 update 的 `caption_updates`（仅更新原文唯一匹配的普通文字标题，日期来自识别结果）。
- 实施第一步先冒烟测试本机 dotnet 运行时（旧项目有真实运行记录，预期可用）。

## 三、错误处理

| 边界 | 处理 |
|---|---|
| 提取 | 任一表不能安全提取 → 整体明确失败，不跳过 |
| 模型调用 | 配置缺失 → 阻止启动识别并提示；调用失败/超时 → 留证＋标记失败范围，不猜测结果 |
| 比对 | 身份重复、参加比较的必要信息缺失 → 不对应，原因入清单 |
| 搬运 | 无对应/读取失败 → 保留 A 原值＋问题清单；0 与真实空白按需求政策 |
| 写回 | 任一表不能更新 → 不发布最终报告；回读不一致 → 报差异清单，不静默 |
| 文件 | 改前备份失败 → 中止；原件全程只读 |
| 中断 | 接续索引落盘后可续跑，不重跑已完成范围 |

## 四、测试策略

- **单元（pytest）**：身份证比对（逐字/唯一/比较排除）、空白与 0 政策、换期角色配对、简短指令长度守卫、保存忠实性、接续索引断点续跑。
- **集成**：本地 stub 模型服务（假 HTTP）驱动“识别→比对→搬运→Excel 写回”全链；Word 桥接往返用小样本 docx/xlsx（普通金额回写、增删行列、caption 更新、合并保护拒绝）。
- **验收**：天宇油脂全链＋人工直接回写＋增删行列实例，按需求九项逐项验证。
- 每个实现任务按“失败测试 → 最小实现 → 全量验证”推进（阶段 3 计划约束）。

## 五、迁移与回滚

- 无历史迁移：不导入旧项目识别答复；旧项目目录只读，抄代码用复制，不动原件。
- **回滚：保留本次运行目录的全部记录**（模型原答复、人工修改、验证证据），恢复使用上一份有效结果作为当前基线；重新运行另建目录。清理运行目录属删除操作：列清单、经用户确认、只进 Windows 回收站。程序不改任何原件。
