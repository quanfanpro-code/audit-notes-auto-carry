## 一、方案概览

把软件做成“办理一份任务、核查这份结果”的桌面工作台。用户不用理解任务目录和内部记录：从文件选择进入任务，从任务进入业务表，从业务表进入一条结果和它的依据。

采用 Vue 3、Element Plus、pywebview/WebView2，继续使用本项目 FastAPI 和 Python 内核。前端负责操作与阅读；服务负责找对任务、组织真实结果；原内核仍独占识别、配对、搬运、公式核对和复用判断。

不增加数据库、消息队列、后台任务平台、第二个财务引擎或完整电子表格编辑器。必要新增的是桌面窗口、面向任务的查询/操作接口，以及少量最终交付事实记录。

### 比较过的三条路线

| 路线 | 能解决什么 | 成本与结论 |
|---|---|---|
| 继续扩充当前原生网页 | 能改善表单和列表 | 复杂筛选、详情、状态保护都要自行维护；本轮不选 |
| Vue + Element Plus + pywebview，复用 FastAPI | 成熟表格、表单、侧栏；与 audit-system 技术一致 | 增加前端构建和桌面壳，普通使用不需要 Node；本轮推荐 |
| Qt 或 Electron/Tauri 重做桌面 | 可以做复杂桌面界面 | 新增另一套控件/运行时与通信维护，当前收益不足；不选 |

交互取自 Microsoft 的列表详情、Fluent 的补充侧栏、Carbon 的数据表指导；实际只用 Element Plus 一套组件，避免混搭样式。参考链接和本机材料见本文附录。

本文承接需求中的具体交互和后端约定：第二至四节供用户看操作与页面，第五至九节供执行者看数据、接口和改动边界。字号、分页和性能数字是本设计提出的实施目标，不是现有程序已经达到的结果。需求保留业务目标和验收条件，计划负责逐项落实，不再各写一套页面规则。

## 二、用户每天怎样操作

### 1. 做第一份报告

打开软件 → 在“A：需要填数的文件”选择 Word/Excel → 在“B：提供本次数据的文件”选择 Word/Excel → 勾选各端工作表 → 开始。

金标准和模型连接已经配置过时不重复填写；折叠区显示本次实际金标准、复用开关及记录位置。首次缺条件时在对应位置说明，并可直接去设置；返回时保留已经选好的文件。Excel只有一张可见表时自动选中，多张时列出并让用户选择，隐藏表禁选并说明原因。

运行页显示这份任务的文件和实际阶段。用户可以看历史，不必盯着进度。任务结束后在固定提示条通知；不强制把用户从正在查看的历史结果跳走。

### 2. 核查结果

进入结果先看结论和需要查看的业务表。点“公式待核”后，只列相关表；点一张表，就看到 A 原值、B 本次值、A 最终值。点具体行，右侧展开公式和完整原因。需要回到文件处理时，直接打开这份任务登记的新副本，并复制准确位置。

例：A 的 SUM 算出200，B为210，结果显示“公式保留；本次金额不一致；差额-10”。不能写“公式错误”，也不能把配对成功显示成写入了210。

查看结束后点“再做一份”，保留常用设置、清空两端文件。要再次用原文件时可在历史任务选“以这份任务新建”，新建页明确展示被带入的文件，由用户点开始；不会覆盖旧任务。

### 3. 处理疑问

“待答复”点进去能复制当前识别说明和材料、粘贴答复、保存并继续；也能中断。答复格式不合要求时保留输入并显示原识别检查的原因。

发现旧解释确实有误，从结果的复用详情进入对应记录，查看解释和来源，预览影响、填写原因及依据后停用。历史报告标“相关识别记录已停用，待复核”；软件不自动改旧报告。

## 三、页面布局与操作细节

### 3.1 全局框架

固定左导航：“新建任务”“历史任务”“识别记录”“设置”；底部放“工具 → 人工回写”和帮助。上方为页面标题、当前任务名称及全局活动任务提示。当前任务默认用 A 文件名加创建时间命名，不要求输入公司或年度。

导航宽176px，可收为64px；顶部56px。默认窗口1440×900逻辑像素，初始尺寸不得超过工作区。1440宽时结果列表240px，详情侧栏320px，其余给明细；不足1280宽时侧栏改成按需打开；不足1100宽时业务表列表与明细单区切换。有效视口900×560仍能完成主要操作，不靠缩小到不可读字号挤入所有列。

### 3.2 新建任务页（示意）

```text
新建任务                                  常用设置：已就绪
┌ A：需要填数的文件 ─────────┐  ┌ B：提供本次数据的文件 ─────┐
│ 附注.xlsx       [更换文件] │  │ 本期底表.docx [更换文件]    │
│ 查工作表…  已选2/5        │  │ Word：按现有提取范围处理    │
│ ☑货币资金  ☑往来  □存货   │  │ 查看完整路径               │
└─────────────────────────┘  └──────────────────────────┘
             B 的本次数据 → A 的新副本
本次设置：自动复用已开启 · 金标准：附注金标准  [展开]
原文件保留；结果另存新副本。                    [开始任务]
```

选择文件后立即显示文件名；工作表仍加载时显示明确占位并禁用开始，失败只影响该端。更换文件清空该端选择。文件读取请求带序号，旧请求即使后返回也不能覆盖新文件。错误提示贴在出错控件旁；点击开始后定位第一个错误。成功发起任务才离开表单；失败保留选择。

常用设置与“本次调整”分开。本次关闭复用不得反写全局默认；新建后按实际后台生效状态显示。现有已启用函数以启动环境设置为优先，存在覆盖时界面显示“由启动设置控制”并禁用无效切换，不改原优先级。第一版不加拖拽文件、自动识别公司、模板登记和复杂向导。

### 3.3 任务运行页

顶部固定 A/B 文件、所选工作表、开始时间和“中断”。主体显示阶段条与当前操作；下方业务表清单随已有事实更新，不提前显示成功。

现有步骤映射：extract→准备文件，identify_a→识别A，identify_b→识别B，carry→整理写入内容，writeback→生成副本，readback→回读核对。等待答复是覆盖在识别阶段上的明确状态，不让进度动画无限转。后端没有分科目/分表总数时只写当前阶段；不为进度条虚构总量。

运行提示示例：“正在识别 B：资金表”“等待 A 的人工答复”“正在等待本次 Word 写回结束”。细日志折叠，默认仅显示最近一条有用事件；不将每个接口调用当成用户进度。

### 3.4 结果页（核心工作区）

查看顺序固定为“任务结论 → 业务表 → 明细 → 依据”。任务结论保留本次两端文件和所选工作表；有问题时优先显示需查看的表，没有问题时显示正常结果。表列表显示科目、表名、主/续表数量和处理情况；不同币种、单位不合并成总金额。

```text

部分保留     2张表需要查看       公式待核1项 · 回读差异0格
┌ 业务表                   ┬ 资金情况                           ┐
│ 搜科目或表名…            │ 人民币 / 元 · 主表＋续表             │
│ [全部] [需要查看]         │ [结果明细] [标题] [公式] [识别复用]  │
│ 货币资金  余额构成  正常  │ 搜项目… 结果筛选…  清除筛选         │
│ 应收账款  账龄表    保留  │ 项目  期间  A原值 B本次值 A最终值 结果│
│ 存货      分类表    待核  │ …                                   │
│                          │ 50条/页  共120条       上页 / 下页    │
└─────────────────────────┴─────────────────────────────────────┘
点一条明细 → 旁边展开完整原因、已有位置和依据；支持上一项/下一项。
```

上图数字仅示意，不是程序运行结果。主操作由状态决定：正常结束为“打开A新副本”；存在问题为“查看需处理内容”，打开副本为并列次操作；未产生正式副本时不能出现可点击的“打开成品”。不自动打开Office，不自动切换页面。

结果明细列定义：

| 列 | 内容与规则 |
|---|---|
| 项目或名单 | 使用本次识别名称；名单发生变化时显示“原名称 → 本次名称”；长名称展开可读 |
| 期间 | 使用本次已识别角色及实际日期；不根据日期顺序再推断角色 |
| A原值 | 本次输入快照中的原值，不读用户后来改过的原件充当旧值 |
| B本次值 | 本次来源值；名单使用搬运时确实选中的标签来源；清尾没有B格就说明“B无此项” |
| A最终值 | 由交付回读留存；有精度差异时保留实际值；未记录就写“未记录”，不抄B值填充 |
| 处理结果 | 已写入、数值未变、已清空、原值保留、公式保留、回读有差异、未能确认；理由可展开 |

表级问题没有具体格时放表头问题区，不编出一行金额明细。标题单列页签展示每张物理表的原文、拟更新文本、最终动作及原因；同一业务组的主表和续表一并可查。标题原文与最终实际文本不是同一个字段，无实际文本证据时仅说明写回结论，不拿拟更新文本冒充实读文本。

详情侧栏内容依次为：具体原因与下一步、A原值/B本次值/A最终值、位置、公式或标题、识别依据与复用。侧栏关闭后焦点回到原行；点击下一项继续同一筛选集合。复杂记录比较使用独立详情页，不在侧栏中再嵌套侧栏。

核查路径按需求G19验证：选定历史任务后，到指定问题明细最多3次主要点击，例如“公式待核 → 业务表 → 明细”。上一项/下一项不清筛选；切换任务再返回，恢复该任务所选表、页签、筛选和查看位置。空筛选结果提供清除入口，不把“没有此类问题”显示成“没有处理结果”。

“需要查看的业务表”按不同业务表计数；公式待核、标题保留和回读差异可同时存在，每项可点入，不由一个总状态遮住其他问题。详细计数口径统一见5.3。复用、新识别、重认、未精读由原记录区分，实际调用次数另列；不把零调用当作自动复用。

位置显示为分开的“文件／工作表／格子”或“Word第几张表／区域名／行列”。格子的身份继续来自已有解释；不重做匹配。含“!”的表名原样保留，展示层不从第一个“!”拆字符串。第一版只承诺打开文件和复制位置，不承诺Office自动跳到某格或某段。

### 3.5 历史任务

默认最近在前。列：任务、A/B格式与文件、开始时间、处理结论、需查看表数、文件状况。状态和文件状况分列；“处理结束”和“成品被移走”可以同时显示。

点击行进入该任务详情，返回保留筛选和页码。活动任务在顶栏独立标识；正在看旧任务时“中断”仍明确写当前活动任务名，历史未完成任务只有“继续此任务”，没有含糊的“继续上次”。

只扫描运行根下的正式任务目录，不递归扫描验收、测试和桥接留证目录。旧任务缺创建时间时可用目录时间作显示，但标为“按目录时间”；缺输入、记录或成品时逐项说明，不强制迁移、不静默排除。

### 3.6 识别记录

列表支持科目/表名、识别步骤、格式和状态筛选。第三遍记录可跨端跨格式，不能用来源A/B把适用性错误限制回去。状态分为“可自动复用”“本次规则下不适用”“已停用”“有冲突”“记录不可读”；原始状态与本次适用性分别展示。

选中记录后查看：识别含义、固定证据、来源、使用过的任务、停用或裁决历史。解释用“列含义、行含义、期间、单位、例外”表格展示；编号与原始记录留在技术详情。

冲突页按同一条依据下的版本并排比较，差异行强调，完整解释可展开。保留版本必须用户主动选，不能预选最新。也可明确停用全部。填写原因和依据引用后确认，失败保留填写内容。

停用预览使用当前记录簿，显示预览时间和影响数量；实际提交仍由原跨进程锁重新计算。提交前后若新增使用，返回的实际影响清单为准并提示新增影响，不宣称预览永久锁住历史。冲突裁决继续按现有预期版本集合检查，变化时要求重读，不能自动重发过时决定。

### 3.7 设置、答复与人工回写

设置分“日常设置”和“模型连接”。保存与测试连接分开；当前接口只访问/models，界面只能说“模型列表接口可访问”，不能说模型推理已验证。增加“密钥已保存”布尔提示，不回传密钥；留空沿用原密钥，不把空白当删除。金标准和记录目录用选择窗口，默认记录目录保持项目下识别记录。

首次金标准默认指向本轮已核实的C:\Users\27651\Documents\Code\audit-notes-auto-carry\金标准\精简新副本_20261101_010814\财务报表附注语义金标准_当前基准_以此为准.jsonl；实现按项目位置解析相对路径以支持整体搬家。该文件不存在时让用户选择，不用目录里“最新的一份”替代。已有用户选择优先于首次默认。

答复面板固定任务、侧和材料名。复制材料与粘贴答复为两个明确区；保存按钮为“保存答复并继续”。后端确认任务正在等待该材料，原子保存到其原目录，调用既有识别流程。已有不同答复时先显示替换确认，按项目备份规则保存原文件；解析失败不删除答复或材料。未保存粘贴内容按任务和材料保留在当前窗口，切页面不丢失；关窗前提示保存或放弃。

人工回写作为工具页：带连接Word、已由人工保存的提取Excel、另存新副本位置。可从同任务文件列表带入已有文件；结构操作属于高级入口，只接收现有清单，界面不猜插删行。写回失败保留选择、显示具体原因；不能覆盖原件。与自动任务共用执行占用检查。

现有人工回写没有断点续跑或桥接内即时取消能力。本版不伪造这两个按钮：运行时提示等待本次写回结束；失败后“重新另存”新建一次操作，原成果保留。关窗只能等待该步安全结束，不能强杀Word。

## 四、统一视觉与反馈

### 4.1 视觉变量

样式集中在前端一份视觉变量文件，各页面引用同一组变量；不建立主题配置系统。采用深海军蓝导航、浅灰工作区、白色内容和蓝色主按钮，青绿色仅表示成功。下面为本版固定规格：

| 用途 | 规格 |
|---|---|
| 导航背景／导航文字 | #15283F／#E7EDF5；选中项用浅蓝强调并有明确选中标记 |
| 工作区／内容／细分隔线 | #F4F6FA／#FFFFFF／#E2E8F0 |
| 正文／次要说明／主操作 | #172B4D／#52637A／#2563EB |
| 正常／保留待核／失败 | #0F766E／#92400E／#B42318，分别配浅绿、浅黄、浅红底；同时有文字与小图标 |
| 字号与数字 | 正文、金额14px；辅助12px；页标题20px；数字等宽、右对齐，原精度不变 |
| 间距与圆角 | 间距8/12/16/24px；内容区圆角8px，控件6px；少用阴影，不做渐变统计卡 |
| 操作与表格 | 主按钮36px高，紧凑次操作至少32px；默认行高36px，长内容展开后允许增高 |
| 轻微过渡 | 详情、导航及状态约150ms；系统要求减少动画时关闭；连续核查不等待动画完成 |

### 4.2 三个主要页面的视觉重点

新建页用两个紧凑文件卡片突出A、B与“B→A的新副本”，常用设置折叠在下方；运行页把文件名、当前阶段和下一步放在同一区域，日志按需展开。结果页顶部结论区保持紧凑，选中的业务表用淡底和细线提示；原因放可展开的浅色说明区，不用大色块盖住金额。

首次空状态只放一个小型线性图标、一句话和主操作，不另造插画依赖。加载保持表格结构与占位，避免布局跳动；无结果、无历史、文件缺失和服务断开分别说明。稳定状态标签按“图标＋文字＋淡底”呈现，不能只变颜色。

### 4.3 操作与可读性约束

- 浅灰背景、白色内容、蓝色主操作；每个任务状态只有一个主要下一步。框线和8/12/16/24px间距建立层次，少用大阴影、渐变和巨大统计卡。
- 默认微软雅黑/Segoe UI，正文14px、说明12px、标题18–20px，行高36px；支持界面字号调整，不改Windows设置。金额使用等宽数字、右对齐；状态必须有文字，不能只看红绿。
- 主要按钮高度至少32px；窄窗口优先保留项目、金额和处理结果，其余信息进入详情。长金额可完整展开，保持原有精度；空白、未记录、读取失败各有文字，不共用一个横杠。
- 普通查看使用内嵌详情；停用、替换答复、放弃未保存设置、运行中退出才弹确认。错误使用持续提示，短暂提示只用于“已复制”“已保存”。
- 加载时保持表格结构，禁用对应按钮，不锁死整个页面。筛选没有结果显示“清除筛选”；从未运行显示“新建任务”；文件缺失显示原位置与打开任务目录。
- Tab可达主要控件、Enter操作有焦点按钮、Esc关闭详情/对话框并恢复焦点；不设置会意外启动任务的全局Enter快捷键。原样复制必须不附加货币符号或千分位，也不改变00123。
- 表单控件有可读名称，错误能关联到对应控件；焦点与正文保持清楚对比。运行结束、中断、待答复等关键状态可被辅助阅读工具获知，不每秒播报进度。不以“组件库默认支持”代替实际键盘与状态反馈检查。
- 不在第一版做深色主题、主题市场、复杂动画、拖线配对、内嵌Office编辑和“标为已解决”按钮。查看过不等于业务问题已经解决。

### 5.1 任务身份、快照与继续

一个任务目录对应一个task_id。新接口仅接受服务枚举的运行根下任务；拒绝路径穿越，不能把随意路径当任务。用户查看的view_task_id只在页面使用；活动任务active_task_id由服务决定。每个操作带task_id，禁止“先切全局当前任务，再调用旧中断接口”的做法。

新增任务说明.json，保存创建时间、原始输入参数、金标准路径、复用开关及记录目录、请求标识和执行次数；不保存密钥。每次执行保留同一任务身份，增加执行次数，使上一轮迟到结果不覆盖续跑。

继续新任务使用已保存的原始输入表示，不从当前新建表单取值。旧任务可以从输入指纹可靠还原时才继续：特别保留“类型”字段原先缺失/null的差别，不能擅自补为excel/word使指纹变化；显示格式可由文件后缀确定，但不写回原输入。无法还原时明确只读并提供新建。金标准、工作表、规则或文件内容改变仍由原校验拒绝，拒绝不得改旧索引。

模型连接沿用现有加密配置；当前运行持有启动时快照。继续任务使用当前模型连接时在按钮附近明示，若连接已变则显示本次使用值；原任务金标准、复用开关等不得被当前默认设置替换。

任务开始、继续和人工回写在服务的同一占用检查中接受；按钮禁用不是唯一保护。相同请求标识和内容返回原任务，标识相同内容不同拒绝；响应丢失先查请求结果。任务说明写入成功才启动后台，写入失败不启动，避免无法追踪的任务。

### 5.2 交付事实：只补留证，不补业务判断

新任务新增交付明细.jsonl及对应索引登记。记录一个现有动作的事实：task_id、执行次数、侧/读取部分/业务表组、A位置、明确关联的B位置、A原值、B本次值、最终动作、实际值及其是否取得、原因引用、输出文件和哈希、标题或公式关联。

普通金额从现有对应和最终变更取得；名单来源由现有搬运的标签来源直接附带留证；清尾明确为无B来源。建议给生成更新表增加可选“留证”容器，原返回值与判断顺序不变，不在服务里重写该函数的项归属逻辑。

Word在整组撤回完成后冻结最终动作；利用现有回读读取到的实际值，增加可选明细输出，不重新提取第二次。Excel在原工作进程剔除撤回组、保存并读回后附带返回最终实际动作和读值，原公式比较和计算次数不变。没有读取的保留格仅有“已保留”事实，实际值字段标未取得；要展示它的实值，利用已有最终快照或回读表机械读取，不能用原值假扮实值。

原程序错误写空、真实空白、清尾等行为只记录原动作和原因，本轮不修改其政策。标题生成成功与最终写回成功分别记录；主/续表按已有身份归组，不重判归属。

由一次执行生成完整明细，再原子登记。中断、异常和写入明细失败都不能发布半份“已完成”明细；成品成功但明细保存失败时，保留原核心状态并单列“结果明细不完整”，仍可打开成品。展示查询不重跑内核。历史没有这些字段时只展示可证实事实，不补造每格最终动作。

### 5.3 结果整理与计数

服务的结果整理只按已存在的任务、读取部分、侧、业务表组、格子身份关联资料，不靠科目名或表名猜关联。不从第一个“!”拆工作表名；边界仍保持分开的工作表和格子字段。

表组键包含task_id、侧、读取部分和已有组号；同名工作表、A/B都有G1不混。主表与续表保留各物理表身份；按组汇总只是展示。

值以“类型、原样文本、是否取得、来源”传给前端；金额显示和差额来自后端，前端不重新计算和四舍五入。空白和未取得分别表达。普通格以最终动作计数：已写入、数值未变、清空、保留、公式保留等互斥；问题类别可交叉，用独立问题标识计数，标签说明为“问题条数”。标题动作单独计数，不混入金额格。

界面分别呈现：核心处理状态、文件状况、明细完整性、问题类别。比如done可以同时有清尾提醒；新版本部分保留不得显示完成；旧任务done与撤回证据矛盾时标“旧记录状态不一致”，只读展示不回写旧任务。

默认每页50条，服务侧筛选排序后返回20/50/100条和总数。相同任务同一执行次数使用一个结果版本；请求页码/筛选时带版本，变化则重读并提示，不能把两次续跑的数据拼一起。初版用普通Element Plus表格加分页，不同时引入虚拟表或大型工作簿渲染库。

### 5.4 复用记录与影响

列表来自现有记录簿快照；本次是否适用调用现有版本可用检查，不能把存盘“有效”直接当“当前可复用”。缺失金标准或规则依据就标不可确认。

详情保留原解释版本、来源和引用。预览与实际管理调用现有查询、停用、裁决；多目标预览如需共用影响计算，只封装既有_影响，不复制递归算法。请求标识在用户打开确认操作时生成，重试沿用；提交结果从记录簿回查，不能根据按钮响应动画决定成功。

相关历史任务的“待复核”是记录管理产生的附加提示，与原任务处理结论分开；查询时关联影响清单，不批量改写旧索引，不自动重跑。原文件不在仍展示影响身份，不能因打不开报告删掉影响条目。

继续使用已有/api/工作表、/api/选文件、/api/设置及测试连接。设置补充“密钥已保存”；非秘密默认项单独存界面设置.json。人工回写仍调用现有函数，改为经过共同执行占用和进度查询的任务入口，任务说明标明类型“人工回写”，不伪造识别或复用步骤。其输入仅为带连接word、excel、输出、可选结构操作，不送入A/B输入规范化；不提供继续或即时中断，执行期间显示正在回写，成功/失败来自原桥接实际返回。

### 关键数据对象

- 任务摘要：task_id、类型、执行次数、名称、A/B文件和工作表、创建时间及来源、核心步骤、活动/等待标识、问题分类数量、允许操作、展示资料完整性。
- 业务表：稳定组键、现有组号、科目/表名、侧/读取部分、物理表集合、单位/币种、结果分类、问题数；未识别表保留文件位置而非伪造科目。
- 明细：稳定行标识、组键、项目原文、期间原文、A位置、B位置、A原值、B本次值、A实际值、最终动作、回读情况、原因引用；缺失值必须显式标记。

## 七、状态与生命周期

| 后端事实 | 页面显示 | 允许的主要操作 |
|---|---|---|
| 未开始 | 请选择文件 | 选文件、设置、开始 |
| 后台仍活跃 | 当前真实阶段 | 中断、查看历史；禁止再开始/继续/人工回写 |
| identify_a/b且待答复非空，后台退出 | 等待A/B答复 | 查看材料、保存答复并继续、中断 |
| 已发停止事件，线程未退出 | 正在中断 | 查看进度；不能重复发起执行或强行退出 |
| 用户中断且后台退出 | 用户中断 | 继续此任务、新建、打开已有文件 |
| done且后台退出 | 处理结束，另列提醒 | 结果、打开正式副本、再做一份 |
| 部分保留/公式待核/回读不一致 | 对应中文结论，同时列全部问题分类 | 查问题、打开现有副本；不称全部成功 |
| 识别失败/Excel交付失败/任务失败 | 具体类别＋真实原因 | 查证据、符合条件则继续；候选另列 |
| 服务连接断开 | 无法取得最新状态 | 重连；不猜任务停止或失败 |
| 重启后旧步骤仍在运行，但无活动后台 | 上次运行未正常结束 | 查看现有成果、经原校验继续；不改写旧状态冒充主动中断 |

正常轮询按1秒间隔且前一请求完成后才发下一次，离开页面取消过时请求；任务结束或明确等待时停止持续轮询，答复保存、继续、中断后主动刷新。后台断开逐步放缓并提供重试，不持续刷错误提示。

桌面壳启动本机127.0.0.1随机端口，实际监听成功后加载同源/桌面页面。窗口主线程运行WebView2；FastAPI使用原uvicorn日志配置在后台运行，不依赖stdout。静态页面构建在本地，无CDN、无Node开发服务。启动只检查窗口和服务必要条件；Word桥接、Excel能力按实际文件组合检查，不能因不用的Word能力缺失就阻止Excel到Excel任务或历史查看。

桌面与旧启动入口共用服务实例锁，第二次启动提示已有实例，不另建后台。进程内开始/继续/人工回写共用短锁，只用于接受操作，不把整段模型调用锁住。活动后台即使刚写done但尚未退出，也需等待真正退出后释放执行占用。

关闭窗口时：后台空闲且无未保存内容直接退出；有未保存设置或答复草稿先保存或放弃。等待答复的材料已经落盘、没有活动后台时可以直接关闭，重开后仍可继续，不强制先点中断。任务活跃则可返回等待或“中断后退出”；人工回写只可等待安全结束。关闭事件不阻塞窗口线程，先拒绝关闭、发送一次可支持的中断，观察后台结束后再关窗并停服务。不能强杀用户Office；若Word当前操作无法立即中断，就显示正在等待该步结束。若任务先完成，按实际完成状态显示，不强写用户中断。
