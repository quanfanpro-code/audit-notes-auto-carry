# 审计附注自动搬运系统｜跨任务复用识别结果设计方案

2026年11月4日 · 按批准意见修订 · 文件方案已选定 · 源码基线 ecd71f0

## 一、推荐方案

在本机单独保存一份“识别记录簿”。模型第一次认清一个表组时，程序保存这次判断所依赖的原文位置、表内结构和解释。下次先用本次文件核对这些证据；只有证据完整、解释唯一、版本有效，才跳过相应识别步骤。之后仍由现有程序用本次 A、B 材料配对、搬运、写回和回读。

| 可选做法 | 开发、维护和验证 | 与现有任务的关系及撤回方式 |
|---|---|---|
| **本地记录文件＋内存索引（推荐）** | 每次发布一份完整记录，按固定证据建立查找目录。复用已有文件处理方式。要验证文件发布中断、并发、缺失和冲突。任务多时，打开索引的时间要实测。 | 当次成果仍由任务目录负责。可以单独关闭跨任务读取，保留历史记录。 |
| 本地 SQLite 共用库 | 事务、去重和关系查询更方便，适合积累较多记录的情况。需要额外维护库结构、迁移和恢复测试；本机 Python 已可用 SQLite。 | 仅管理跨任务记录也可行，但要单独说明与项目原有文件约定的边界。以后可从同一份记录重建索引。 |

第一版选择文件方案，理由是仓库已有“任务文件为权威产物”的约定，当前也没有实测证明历史查找是瓶颈。按实际模型调用数和本地查找耗时分别验收；将来若查找成为瓶颈，可替换索引，不改变业务判定规则。[项目既有设计决定](https://github.com/quanfanpro-code/audit-notes-auto-carry/blob/ecd71f0149e01aa8a5bd8e8eb160b9b27721346e/docs/adr/0001-文件流水线为权威产物.md)

## 二、下一份文件实际怎么走

**A 端示例。** 第一份 Word 有“应收账款、存货、固定资产”，第二份没有“存货”。先提取第二份 Word 的物理表及各自表前原文。用未解释的网格形状、合并关系和固定文字查候选，无须先知道当前表名。把候选保存的证据逐项放回当前表核对。若“固定资产”及其所属章节、主表和续表都能唯一定位，沿用整组行列解释，登记第二份 Word 的实际位置。少一个科目产生的表序变化不触发重认。若剩余内容不能全部归属，则回到第一遍或第二遍确定整侧边界；已经能够可靠定位的“固定资产”组仍有机会跳过第三遍。

**B 端示例。** 第一份 Excel 已认过“存货”。第二份仍保留该表，只把数据格填零。先构造本次可见区域，把旧布局中已标出的固定内容、业务范围与本次材料核对。本次范围全部得到解释，且所需表组均命中时，三遍都不调用模型。若第一份任务因 A 没有“存货”而跳过了 B 的精读，第二份 A 有“存货”时，前两遍布局仍可沿用，只补认本次需要的这一组。

## 三、记录簿保存什么

建议位置为当前 Windows 用户的本地应用数据目录。本机示例为 `C:\Users\27651\AppData\Local\审计附注自动搬运\识别记录`。程序按系统实际目录定位，避开项目、网盘、已知同步目录及其重定向位置。不能确认位置可用时，关闭共用记录读写，继续按本次材料识别。记录目录与备份按客户资料管理。

| 记录 | 保存内容与用途 |
|---|---|
| 识别依据 | 侧别、识别步骤、版本；当前段落或表组范围；固定文字、合并及相对位置；已标明用途的变化位置；原文证据和来源任务。只保存解释所需材料，金额及上次写回动作不进入解释。 |
| 可复用解释 | 分科目和分表的覆盖说明；表组及续表关系；行列角色、期间、槽位编号、序号和例外。解释中的位置相对本组保存；绝对坐标仅作为历史来源。 |
| 使用与状态 | 本次任务、侧别、表组和所用记录版本；本次判断所依赖的上游记录；入库、冲突、停用与回退原因。使用一次只增加使用关系，不产生新的独立解释。 |

共用记录簿只负责跨任务来源和依赖。任务目录继续保留本次识别材料、结构、合集、配对及回读结果，并记录本次用过的内部记录编号。旧任务名称、客户原文、路径不得带进本次报告、对外清单或新交给模型的识别材料。

## 四、如何机械核对，避免“长得像就算”

1. **首次标明用途。** 扩展现有识别答复，让识别明确指出固定证据、本次填写位置、名单标签位置、报告主体名称、排版编号、日期及期间角色。每个可变位置都必须绑定表内位置或原文片段、角色、允许的写法和作用范围。缺标注处保留原文作固定证据；需要根据意思才能替换时回退。一个业务组不能靠全部遮去文字得到匹配。
2. **先缩小候选，再逐项核对。** 先按版本、侧别、物理结构和固定原文片段检索；不得按模型尚未给出的科目或表名作为唯一入口。用摘要加速查找，命中后仍比对完整证据。候选里标出的金额格不比较金额；名单名称可变但项数、标签位置和层级要相符。可变标记不可跨格、跨段吞掉新标题、注释或新增项目。金额位置出现与其角色不符的文字或无法确定用途时回退。
3. **位置用本次的。** 先取得候选在当前材料中的位置，再核对表组上下文、相对行列、固定项目、单位、币种、倍率和期间。只允许首次已标明且可验证的变化。遇到两处均可定位、多个解释相容但不同、续表归属不明或边界无法核对，一律不自动选。固定证据与解释均等价才合并来源；同一证据出现矛盾解释时登记冲突并阻止再次自动命中。
4. **标题在两侧配对后生成。** A 的第二遍只标明是否需要更新、日期片段的位置、适用期间角色和替换规则，不提前生成新标题。完成本次 B 识别和 A、B 配对后，对有实际变更且需改标题的组，从本次 B 对应业务表组按同一期间角色取得已经确认的“期间实际”日期和证据坐标。一个标题有期初、期末两处时分别取证，不能要求两个角色日期相同。每处只有一个一致日期、位置唯一，且 A 当前标题与证据一致，才在写回前生成本次原文和新文。第一版不另设推算日期的来源。日期取不到、同一角色日期冲突或标题位置不唯一时，生成组级失败结果，使用现有标题保护效果：该组所有物理表的标题和格值一起保留原样，登记原因，其他组继续。无需改日期的标题不受此条件限制。

## 五、三遍与可见范围如何接入

| 判断点 | 允许跳过模型的条件 | 未满足时 |
|---|---|---|
| 第一遍，整侧分科目 | 当前所有需说明的内容能机械定位到唯一科目段或原有明确的非业务段，边界无歧义，覆盖无遗漏。可用已有证据组合，但每段均须有完整依据。 | 对当前侧调用现有第一遍，不拿旧段填补不确定处。 |
| 第二遍，整侧分表 | 在本次有效的科目边界下，业务表、续表和非表段均完整归属。当次有效范围全部覆盖，无重叠解释。 | 在本侧调用现有第二遍，按新边界检查各组精读是否可用。 |
| 第三遍，业务表组精读 | 完整表组在当前位置有唯一有效解释，当前金标准、期间和标题要求均满足。 | 整组走原精读；一组含多张物理表时沿用现有逐张调用，每次实际调用均计数。 |

B 端先生成唯一的**本次可见范围**，供全文材料、查库、重定位、合集和完整性检查共用。打印区域按单元格取并集去重，再扣除隐藏行列；无打印区域时以可见值或公式确定内容范围，公式返回空白仍占位置，纯格式、纯空格和孤立空白合并不扩大范围。表内空白保留，公式缓存缺失不能变成零或普通空白。打印区域无可见内容时给出明确原因，不把空范围解释为“本期无业务”；无法解析已设置的打印区域时，不扩大成整张工作表。完成有效范围划分后，再按本次 A 所含科目决定 B 需要精读哪些组。

先用整张底表证据核对；若插删行、改变打印范围或显隐，舍弃旧绝对坐标，以仍可唯一核对的固定证据在当前可见原文中重定位完整表组。出现新表或受影响边界不明时，回退相应整侧划分。不可见内容不得从旧记录、隐藏的合并起点或区域外说明中补回。

**统一的可见单元格集合。** 对本次选定的 B 工作表只构造一次集合，成员按“原工作表＋原行列坐标”识别，保留不连续的行列片段及每个位置的可见性。矩形范围仅供定位和遍历，任何消费者实际可用的位置必须再与同一集合取交集。全文材料、查库重定位、第三遍材料、铺格与合集、覆盖和完整性检查均使用这一份集合。任何中间步骤都不能改用外接矩形，或把不可见格补成可见空白。识别答复若越出集合，拒绝越界解释并按原失败处理。

**跨边界的合并格。** 保留合并形状与可见片段的关系。锚点可见时只在其原位置记录一次文字，其他可见成员标为合并从属格，隐藏的间隙仍不参与识别。锚点不可见时，只记“合并从属、起点不可见”，不取隐藏起点的正文，也不把该格当空白。旧渲染器中“补取范围外合并起点文字”的路径不得用于此类 B 材料。若因此不能确认表头或期间，回退仍使用同一集合；看不清就记录未解释，不发布该解释。

## 六、何时发布，出错怎样处理

**入库时点。** 三遍结果先作为本次候选。入库资格分别按识别步骤判定。第一遍发布本侧覆盖完整的科目布局，第二遍发布与本次科目边界相符且覆盖完整的分表布局，两者都保留业务表组及非表段的覆盖依据。第三遍才按完整业务表组检查续表归属、槽位、期间、例外、标签、序号和适用配对结果。第三遍跳过或失败，仅禁止发布这一组的精读解释。若错误也动摇上游布局，才阻止发布或停用受影响的上游解释。部分任务失败时只发布已独立完成全部检查的组；无法确定失败边界时暂缓发布。混用新旧解释后，重新验证整侧覆盖和完整性、组内连续性及重复键，继续由本次 B 的完整性决定是否允许清尾。

**发布与续跑。** 推荐每批记录写成完整文件，校验后在同一磁盘一次发布。在同一 Windows 用户的跨进程独占锁内按顺序登记已发布批次，用摘要核对内容，保留历史停用事件。同一任务重试使用原任务标识、步骤及表组位置去重，独立任务各留来源。发布前再次核对版本、冲突和停用状态。使用关系必须在依赖旧解释生成本次结果前可靠登记；登记失败就放弃这次命中。若任务在登记后中断，保留这次使用为“可能受影响”。发布中途失败、批次缺失、历史链不完整或状态不可核验时，不加载可疑旧解释；无法证明停用记录齐全时禁用整个共用库。启用完整识别仍执行新 B 可见范围规则。

**索引刷新与一致快照。** 提交批次不可变。维护一个小的当前批次清单，记录单调递增的代次、批次编号和摘要。发布、登记使用、停用和裁决由同一跨进程锁串行处理：先落盘并核验新批次，再一次替换当前清单。读者只读某次已提交清单所引用的完整批次；未提交文件不可见。当前进程提交后同步刷新索引，校验成功才整体切换。每份新任务或续跑开始前重读当前代次，发现其他进程已发布则刷新。索引刷新失败时，本次禁用复用并记录原因，不从旧索引取结果；下次可重新尝试。每次实际使用仍在跨进程锁内对比当前代次、重验有效性并登记依赖；任务开始时拿到快照，不等于整个任务期间的使用许可。已登记后才被停用的任务，按影响清单待复核。进程崩溃由操作系统释放锁，读者不会看到半批状态。

**内部管理入口（无 GUI）。** 提供仅本机调用的停用和冲突裁决操作。停用输入为请求标识、目标解释版本、原因、依据引用；返回已提交代次、停用状态、直接与间接受影响的任务／侧／表组和待复核标记。冲突裁决输入为请求标识、证据组、全部冲突版本、明确保留／替换的合格解释版本或全部停用、原因和依据。锁内核对冲突版本集合仍是最新，原子登记裁决与停用事件后才解除阻止；证据不足、目标不符或冲突已变则拒绝，不猜默认选项。一请求重试返回同次登记结果；同标识不同内容拒绝。保留历次裁决及影响清单，不写历史交付物。

**停用和版本。** 金标准取本次实际内容摘要，识别规则取覆盖分科目、分表、精读标注、可见范围和匹配规则的版本摘要。任一改变或不可核验，旧版全部退出自动复用。确认解释错误后，通过内部停用操作登记记录、原因和依据；程序自动停用受影响的依赖版本，按使用关系找出直接和间接任务，标记待复核。存在同证据冲突时保持阻止状态，直到有明确的纠正决定；新一次普通识别或使用次数不能解除冲突。不覆盖和自动重跑历史成果。

## 七、迁移、回退和验收

**首次启用。** 新库从空开始。旧任务缺少用途标注、版本、入库检查或完整来源，不自动导入。已有任务的输入校验和续跑沿用原规则；升级前中断的任务不能把两个识别版本的中间结果混在一起，需要新建任务时明确告知原因。单独关闭复用即可退回完整识别，B 端按已确认的新范围取材。若回退到旧程序，使用新任务目录并保留已有成果和记录簿，不能用旧程序接续新版本任务。

**验收方法。** 对需求文档第七节全部 14 项，用固定答复或审定结果对照本次科目、表组、位置、标题、配对、清尾和回读。单侧完全命中时三遍模型调用分别为 0、0、0；仅一个单物理表组需精读时为 0、0、1；三遍均需调用且只有一个单表组重认时为 1、1、1。分别记录重试、每组回退原因及本地查找耗时，不能把“跳过”计作“复用”。增加发布中断、二次续跑、冲突并发出现、停用后库损坏和两级间接影响追溯的恢复验收。增加不重启服务连续三份、两个进程交错发布和停用、第二遍可用而第三遍曾跳过、多期间日期冲突、跨边界合并锚点不可见的定向验收。以上均为将来验证的目标，尚未运行测试。

**接入位置。** 表格读取负责 B 范围；识别入口在三遍各自调用模型前检查可复用证据；任务流程在配对后决定表组能否发布；写回和回读继续使用本次任务文件。数据结果不绕开原有校验。[表格读取](https://github.com/quanfanpro-code/audit-notes-auto-carry/blob/ecd71f0149e01aa8a5bd8e8eb160b9b27721346e/核心/表格.py) · [三遍识别](https://github.com/quanfanpro-code/audit-notes-auto-carry/blob/ecd71f0149e01aa8a5bd8e8eb160b9b27721346e/核心/识别.py) · [任务流程](https://github.com/quanfanpro-code/audit-notes-auto-carry/blob/ecd71f0149e01aa8a5bd8e8eb160b9b27721346e/核心/流程.py)
