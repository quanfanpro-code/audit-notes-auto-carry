# 绿色软件打包方案

采用已安装的PyInstaller目录式打包，主exe在顶层，Python库放“程序”，固定WebView2和完整.NET运行时放“运行库”。不做单文件临时解包，不增加安装器或自动更新器。

比较：单文件仍需启动解包且不便收纳持久数据；嵌入式Python加自写原生启动器需要维护另一套启动链。目录式PyInstaller直接保留现有入口，改动最少。

## 路径与启动

新增“运行位置.py”，只统一软件目录、备份目录和绿色版写入边界。源码运行保持原路径；冻结运行以exe所在目录为准。资源仍由打包器定位，业务数据独立放顶层的运行、识别记录、备份目录。

自定义运行钩子先设置包内TEMP、TMP、.NET根和Word桥接备份位置，再执行第三方运行钩子。桌面加载指定的包内CoreCLR及WebView2，并显式指定浏览器缓存目录。Excel原命令仍为sys.executable -m 核心.Excel交付；冻结入口将该请求交给既有模块，业务代码不重写。

Word桥接继续使用原项目编译，仅让两处备份逻辑接受随进程传入的包内备份位置。开发模式默认BackUp不变。包内提供所需.NET完整运行时，桥接无需全局安装。

设置中包内路径以相对形式保存、读取时按当前软件目录还原；外部A/B输入保持原表示。历史留证和复用批次不做搬家时的全文件字符串替换，防止破坏证据摘要或原文。

## 输出与保护

自动任务始终写软件目录的运行文件夹。绿色版校验记录目录、人工另存路径均位于软件目录内；不能用当前工作目录或外部环境变量把输出导向别处。设置和答复覆盖前备份到包内备份目录，保留校验。

制作过程使用新的输出目录，不删除或覆盖现有桌面软件。全部源码修改前备份并核验。打包不包含源码仓库内运行产物、配置密钥和测试代码；许可说明随包保留。

## 验证与边界

先以失败用例验证冻结路径、备份和包外写入，再构建并运行实际exe。固定答复仅通过本机测试模型HTTP服务提供，打包程序仍走真实模型调用和真实Office交付，不打入测试开关。

通过页面及进程模块清单检查运行库来源，用四组合最终文件证明Excel子进程和Word桥接都有效。完整日志和成品保存在新证据目录，最终包配置不留测试服务地址。
