## 四、输入、位置与多工作表

### 4.1 输入约定

新的任务输入使用以下结构；路径由Windows文件选择窗口提供，工作表名称来自实际文件列表：

~~~json
{
  "A": {"路径": "A文件的绝对路径", "工作表": ["资金", "往来"]},
  "B": {"路径": "B文件的绝对路径", "工作表": ["余额", "明细"]},
  "金标准": "金标准的绝对路径"
}
~~~

Word不传工作表，Excel至少选一张。程序核验真实文件及类型，只接受本期的docx、xlsx；所选表必须存在且可见。界面不让用户手填路径或工作表名称。

旧输入word、b表、b工作表先转成同一结构，原合法调用继续可用；新旧字段同时提供且冲突则报错。旧输入省略b工作表时保留原有单工作表可确定规则，多张不能猜。后续内部只用一种输入结构。

### 4.2 识别材料

新增一个文件准备模块，产生每侧的读取部分列表：

- 一份Word：桥接提取一次，得到整份文档的xlsx、上下文、带位置关联的Word。B端带位置关联文件仅作留证，不写回B端。
- 一份Excel：每张所选工作表一个读取部分，均指向本次输入副本，不复制成多本工作簿，不丢失原工作表坐标。
- 本任务的读取部分具有“标识、原文件类型、材料路径、工作表、上下文、产物目录”。Word与Excel不需要额外的类继承或插件注册。

两端材料放在任务目录的A、B子目录；各读取部分再有独立目录，避免识别答复、进度和候选文件互相覆盖。根目录仍汇总A合集、B合集、结构清单、对应清单、问题清单和复用统计，方便原服务展示。

### 4.3 多工作表的处理顺序

1. 准备两端材料，逐一核验输入内容。
2. 逐张完成A端识别，汇总A端本次需要的科目。续跑按根任务中的读取部分完成标记跳过已完成部分，直接汇总其既有产物；未完成部分才继续识别。
3. 逐张处理B端；前两遍仍保留全覆盖，第三遍按本次A端需要的科目决定精读。
4. 合并各部分合集与结构。每条记录增加读取部分；单部分保留原表组名，多部分用“读取部分标识＋原表组”生成该侧唯一表组，避免不同部分都叫G1时串项。
5. 重新核对整侧覆盖、同名组、名单序号与配对键，随后只调用一次既有配对和搬运流程。根合集、结构和候选发布采用合并结果，不让后一部分覆盖前一部分。

单张业务表跨Word分页仍是原续表组；本期不猜测跨Excel工作表的续表归属。同一读取部分内，第二遍发现同科目同名不同组时，给这些组标“歧义”而不中止整侧；跨读取部分汇总时按各侧不同表组再查一次。任一业务键在一侧对应多个表组，就把这些组逐格列为“同名业务表归属不明”，不进入配对、搬运或第三遍发布；其他业务键仍走原流程。同一组内的Word续表不算重复。

位置前缀只用于任务内查找、整项搬运、清尾、标题撤回、留证及停用追踪，不进入“科目＋表名＋槽位＋序号＋期间角色”的业务配对规则。名单项索引必须同时区分读取部分和表组。所有“工作表!坐标”拆分统一从最右侧进行，包括写回、回读和标题定位，不能只修其中一处。

### 4.4 范围与一致性

原生Excel的两端共用现有可见单元格集合：打印区域并集减隐藏行列；无打印区域保留可见内容和已确定表内空白。全文、复用、精读、合集、完整性和写入边界使用同一集合。

合并格横跨打印或隐藏边界时，不借不可见锚点读入原文；不能可靠呈现的范围沿用现有保护并列明原因。Word内部材料继续使用桥接给出的表范围与省略结构。

识别分类结果与本次是否处理分开：历史记录中的“上次跳过”不得直接控制本次精读。会计政策等识别结论保留；本次A端需要哪些B端科目每次重新计算。

### 5.2 跨端与跨格式的实际表现

同一原生Excel工作表由B端改到A端：前两遍布局以及第三遍表组均满足原证据时，三遍均不调用模型；本次写入保护和公式分类重新检查。Word换端采用同样的证据核对，不把旧端别当限制。

Word与Excel双向切换：

- 第一、二遍通常需要按新材料重新划分，不能承诺格式变化后三遍都为零。
- 第三遍可用与格式无关的表内证据复用。例如两份表的行列、合并、表头和表内“单位：人民币元”位置一致，仅物理起点不同。
- Word旧记录依赖表前单位说明，而新Excel只在另一个位置写了类似说明，不能由程序猜两个说明等价。旧依据无法机械定位核实时，第三遍重认；反向切换也一样。
- 以表组为单位核对；Word分页导致主表加续表与Excel单表结构不同的，不能随意摊平套用。

直接查已有记录发生在读取原文之后，不先增加一次模型调用来猜表名。金额、名单名称、当前文件名不加入复用身份；公式是否保留使用本次A端真实公式，不能从旧记录复制。可变名单行名及横向名单的可变标签路径不得留在精读解释和解释摘要中，应用解释后由本次快照补回名单原文；否则多份仅改名记录会被误判为冲突。

### 5.3 记录内容、发布与追溯

复用解释不保存本次输出文件路径、A/B写入动作、旧金额和旧标题新文。位置采用既有相对坐标；解释内携带的端别、物理表号要转成本次值，不能把旧任务字段搬过来。第一、二遍解释中的侧字段和任务内表组名先剔除或规范化，再计算解释摘要。

标题的替换动作不作为跨格式可复用解释。本次第二遍已经取得的Word段落或Excel格内标题结论优先，第三遍复用不得用旧规则清除或覆盖它。只有第二遍本身复用且本次没有标题原文时，才按相同材料的骨架从本次原文重建；跨格式缺少所需标题规则时，由本次第二遍重认，不静默省略应更新的标题。

来源和使用记录继续保留：根任务目录、端别、读取部分、原文件类型、工作表、表组和解释版本。登记使用与发布的请求标识都包含读取部分，避免多张工作表的“整侧”或同版本发布互相碰撞；重复调用仍按同一部分幂等。影响清单输出同样保留这些定位字段，不能只把字段写进事件后在查询时丢掉。相同证据和解释合并版本、来源累积；不同解释冲突时全部退出自动选用。三遍分别入库；第三遍跳过不抹掉合格前两遍。

依赖只登记该组实际使用的上游。发布和使用仍在跨进程锁内重核状态；停用递归影响跨端、跨格式的后续任务。索引在任务开始和本进程发布后刷新。根任务标识用于来源和使用，读取部分目录只保存本部分材料与进度，不把根任务拆成无法汇总追溯的一堆独立任务。

旧证据版本4整体退出新规则的自动复用，保留文件和历史；新证据版本至少为5，匹配版本由2升为3。证据摘要、解释摘要、候选索引与规则摘要同步调整，不靠改一个侧字段来兼容旧数据。规则更新后旧任务续跑应拒绝，不尝试半新半旧继续。

## 六、A端Excel公式：最小实现

### 6.1 写入前分两类

采用现有公式信息和openpyxl的公式分词工具，只作语法检查，不计算公式：

- **纯数字算式**：分词完整且只有数字、正负号、加减乘除、括号，至少有一个数字。按普通金额处理；不得使用eval。
- **保留公式**：其他所有公式，包括SUM、跨格引用、名称、函数、混合常数引用及无法确定的写法。不能因为“没看到A1”就判成纯数字算式。

先执行既有单位、期间、整项、清尾和标题保护，得到拟写清单；再从拟写清单中排除保留公式的位置。不能把有公式当成“不搬”语义，从而无故阻止同项的正常金额更新。反过来，B端读取失败等真正的整项保护也不能因为A端有公式而被绕过。

公式检查清单来自本次可见业务表内的保留公式，不仅来自拟写清单。因此没有B端合计、清尾后保留公式等情况也会明确列为未核验。

### 6.2 调用Excel

复制A端成任务内候选副本，用`DispatchEx`创建独立Excel实例，只打开该副本；不连接用户已打开的Excel实例。已有pywin32依赖，无需新增办公软件库。阻塞的Office操作从首个Excel写回实现起就由一个短子进程承担，父任务管理取消与300秒总超时，不在后续任务再换一套执行路径，也不建立通用调度框架。

打开时不请求更新外部链接，禁用事件和宏，不主动调用外部数据刷新。计算只服务于本次副本。Excel的CalculateFullRebuild会重算该实例内全部已打开工作簿，故该实例只允许打开本次副本。[Microsoft：CalculateFullRebuild](https://learn.microsoft.com/en-us/office/vba/api/excel.application.calculatefullrebuild)、[Workbooks.Open](https://learn.microsoft.com/en-us/office/vba/api/excel.workbooks.open)、[AutomationSecurity](https://learn.microsoft.com/en-us/office/vba/api/excel.application.automationsecurity)

逐格按已确认坐标写值。文字写入后仍须是文字，特别是“=客户名”，数字写入后仍为数字；保留原数字格式，不用整列改文本格式逃避公式注入风险。写值前按组预检保护、合并从属格、数组及溢出范围；不能安全改写的组从本次拟写清单剔除，列出位置，其他组继续。若预检后仍发生写入异常，只恢复该组已经触碰的普通格和标题为本次原件内容；恢复失败才使整次交付失败。不得解除保护、拆公式或把部分写入称为完成。

写完后重算，等CalculationState完成，再保存。交付前重新打开实际保存文件，核对普通格、标题、公式表达式和本次计算值；不把内存里的结果当成已保存结果。[Microsoft：CalculationState](https://learn.microsoft.com/en-us/office/vba/api/excel.application.calculationstate)、[Range.Value2](https://learn.microsoft.com/en-us/office/vba/api/excel.range.value2)

取消、超时或失败要保留原因和候选文件，不标已完成；只关闭或终止登记为本程序拥有的工作簿、Excel实例和工作进程，不结束用户的Excel进程。取消和超时测试不得用结束全部Excel进程实现。

### 6.3 怎样比较金额

每格核对对象固定为本次配对清单中对应的B端金额，且期间、币种、单位等已通过既有检查。不能用A端旧缓存、同列邻格或识别记录中的金额代替。只有状态为“对应”的清单才提供比较对象；清尾、未对应、被标题或其他保护撤回的组均没有可比对象，须列明原因。

两边必须是本次读取确认的有限数值，不把布尔值、空字符串、错误码或未保存的公式结果当零。A端结果取自实际保存并重开的副本；B端金额取自本次B合集。公式错误按保存文件的错误类型识别，不能把COM返回的错误整数当金额。

按实际数值比较，不以界面显示取整掩盖差异。只允许绝对差不超过0.000000001的浮点尾差；不设置随金额放大的百分比容差，不搬用Word回读按显示精度放宽的规则。记录A结果、B值及原始差额，便于复核。无法取得可比数值时列为未核验。

本期不另建公式依赖分析器。快照确认工作簿含外部链接、外部公式或外部数据功能时，若不能机械证明保留公式与它们无关，保留公式标为“未能核对”，原因写“工作簿含外部依赖，未能证明本公式独立”，而不是谎称每条公式本身都有外部引用。普通格搬运仍按现有规则执行。无外部依赖的本地公式由Excel计算；循环计算、错误或未完成计算不能通过。

### 6.4 结果状态

沿用现有问题清单，新增逐格公式核对记录，不另造审核系统。

| 情况 | 文件及状态 |
|---|---|
| 普通格回读正确，公式全部金额一致 | 正常新副本；公式结论仅为“本次金额一致” |
| 普通格回读正确，但公式有差异、错误或未核验 | 保存待核副本；步骤为“公式待核”，列出数量与位置；不撤销已经正确搬入的普通格，不修公式 |
| 某组预检不通过或写入后能完整撤回 | 该组金额、名单、标题和数字公式保持原样，其他独立组照常；步骤为“部分保留”，问题清单定位到组和格子，不显示全部完成 |
| 普通格无法安全撤回、最终回读错误、Excel启动/保存/重算失败 | 保留失败证据和候选文件，状态为失败或回读不一致；不登记成核对完成的交付副本 |
| 原单位、期间、标题等规则已要求保留某组 | 仍先执行原保护，不借公式核对放行该组 |

对范围外或被保护的公式，只保证程序不改写表达式；它们依赖本次变更格时可被Excel正常重算。不新增跨表回滚依赖网，也不宣称其计算值被冻结。

每条公式记录保存工作表、格、业务表组、公式、本次A结果、B格、B金额、差额、结论和原因。可用结论：本次金额一致、金额不一致、计算错误、未能核对。任务为“公式待核”时仍可打开副本和问题清单。

## 七、标题、最终文件和服务

Word保持现有真实桥接、标题片段一次组装、失败组撤回和回读。两端均为Word时，用A的带位置关联文件写回，用B本次上下文和金额作来源，不能交叉。标题生成函数的参数顺序不变，但撤回集合改用A端本次唯一表组，不再用“科目＋表名”；流程和Word异常撤回也按同一标识过滤。

Excel标题只更新识别明确给出的本次格内日期片段：位置由本次读取部分的工作表与识别给出的格坐标共同确定，原文、片段顺序、期间角色必须齐备；不让模型再报一份可能不一致的工作表名。取本次B对应业务键的实际日期。复用仅保留位置规则，不保留上次新文。日期来源冲突、原文不符或定位不唯一时，标题与该组拟搬运内容均不写。金额恰好相同仍检查标题。

标题格本身是保留公式时，不替换公式显示文字；若本次日期无需变化可不写标题，若需要换年而无法安全更新，则撤回该组拟搬运内容。是否参与标题检查由本次对应格及保留公式共同决定，不能因保留公式已从实际写值清单排除就漏掉标题。

为Excel格内标题补充识别答复字段和规则摘要；不让程序扫描整张表猜哪些年份应改。Word与Excel共用日期选取和片段组装函数，分别生成桥接标题指令或“格坐标→原文／新文／表组”的标题变更。

输出总字段为A端新副本；旧Word新副本字段在Word任务中保留兼容，Excel任务提供Excel新副本。根任务保存最终文件哈希、两端输入指纹、各读取部分进度以及本次规则版本。续跑时任何输入内容、格式、选择工作表集合或规则变化都拒绝；仅调整选择顺序不改变工作表集合。用户改过的历史产物按现有避让规则另存，不覆盖。

服务与页面只增加两端文件选择、实际工作表多选、按文件类型打开结果、公式待核提示；不改整套GUI风格。新增`POST /api/工作表`，请求只含已选文件路径，返回实际工作表名称与可见性。新旧任务API输入走同一校验入口。可取消、可续跑的任务要定位到当前端和读取部分，不能重跑已完成部分或遗漏未完成部分。
