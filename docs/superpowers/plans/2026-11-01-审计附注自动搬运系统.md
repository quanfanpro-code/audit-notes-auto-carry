## 本次修订（2026-11-01 晚，基于真实数据验收结果）

九项验收已在天宇油脂真实数据上跑过一轮，结果：6 项通过，3 项部分通过（项3 对应清单、项4 搬运、项7 增删行）。关键数字：A 侧 2014 格、B 侧 4137 格，按原计划比对只对上 **14 格**。

暴露的结构性问题四条，本计划据此重写识别与比对两段：

**问题一：比对没有金标准参与。** 原 Task 9 把比对写成"两侧身份键（槽位＋期间角色＋选取范围＋币种）相同就对应"，A 和 B 直接对。可 A 是 Word 排版稿、B 是 Excel 数据源，同一含义两边写法不同（"预付款项-账龄 / 1年以内（含1年）"对"预付款项按账龄列示 / 1年以内"），逐字比必然对不上：5706 格死在"身份证不同"上。

> **改为：** A 的每一格、B 的每一格，各自挂到金标准的同一个槽位编号；挂到同一编号的才算对应。金标准是唯一公共语言，写法差异在挂编号这一步被吸收，程序此后只处理编号。（见 Task 6、Task 9）

**问题二：识别上来就认格，没有先捋结构。** 原 Task 8 是一块材料直接让模型逐格交六项（槽位、槽位名、期间、选取范围、币种、单位）。模型要同时判断科目、表、行、列、期间、币种六件事，哪件没看清就自由发挥。加上材料里 61/100 只有裸表（无表标题、无表头、无前后说明），切块又是按 20 行一刀切、把表切断，结果就是各写各的。

> **改为：** 三遍线性。第一遍只分科目，第二遍只分表，第三遍才逐格精读并用金标准编号命名。三遍必须串行——后一遍的材料里要写前一遍的结论。（见 Task 8）

**问题三：复杂表头判断没有方法约束。** 现实里的表大量使用横向多层合并、纵向合并行名、续表、右侧并表。原计划只把合并事实标给模型（`C128"本期变动金额"〔合并范围：C128:F128〕`），却不给判断方法，等于让模型自由发挥。

> **改为：** 把 `complex-table-header` 那套方法按层裁成三段模板，内嵌进系统（`核心/看表规范.py`），随系统走；删掉外部技能目录，识别照样能做。（见 Task 5A）

**问题四：结构维护的行号定位算错。** 原实现按"一张工作表 = 一个命名区域"算相对行号，而 A 侧的 `sheet1` 里装了 66 张表。实测删除第 463 行，算出 index=461，可它指向的 TA_001 只有 3 行，桥接报"行列变更位置、数量或样式来源越界"。**这不是桥接不支持增删行**（接口说明写明支持 insert/delete），是我们把位置算错了。

> **改为：** 先定位变更落在哪个命名区域，再算该区域内的相对位置；跨区域或落在区域外的一律交人工。（见 Task 12）

**改完后的验收重点：** 重跑九项，看项3 的对应条数与项4 实际搬入的数字格数量。原 14 条对应且全是表头文字格，改后应显著高于此。

### Task 6: 金标准三层索引（科目 → 表 → 槽位）

**为什么要重写这一节：** 原设计是"按关键词从全库挑相关条目，塞进识别材料"。这条路走不通，原因是逻辑上的死结——要挑对条目，程序得先看懂这张表是什么科目；可程序要是已经看懂了，那还要模型认什么。实测也印证了：89 块答复里只有 1 块真的用上了金标准编号，其余全是自由发挥的名字。

### Task 8: 识别编排（三遍线性：分科目 → 分表 → 精读）

**为什么要重写这一节：** 原设计是一块材料直接让模型逐格交六项（槽位、槽位名、期间、选取范围、币种、单位）。模型要同时判断科目、表、行、列、期间、币种六件事，哪件没看清就自由发挥；材料里 61/100 只有裸表（无表标题、无表头、无前后说明）；切块又是按 20 行一刀切，把表切断，标题落到别的块。三样叠加，实测 6151 格只对上 14 格，而且对上的还是表头文字格。

**新流程：三遍，必须串行。**

| 遍 | 喂什么 | 只判断一件事 | 填上什么 |
|---|---|---|---|
| 一 | 整个文件 | 哪些行范围属于哪个科目 | 每格的"科目" |
| 二 | 还是整个文件 ＋ 第一遍的科目划分 | 在这个科目下，哪段是哪张表 | 每格的"科目＋表名" |
| 三 | 只读这一张表 | 这表的列路径、行清单、作用范围，以及每格对应哪个槽位编号 | 全部字段＋槽位编号 |

**为什么必须串行：** 第二遍材料里要写第一遍的科目划分，第三遍材料里要写前两遍的科目和表名。三遍并行等于每遍从零猜，层层收敛就没有了。本任务内所有模型调用**一律顺序执行，不得并发**。

**Files:**
- Create: `核心/识别.py`、`测试/test_识别.py`（整段重写）

**Interfaces:**
- Consumes: `模型调用.校验指令/调用识别`、`接续.读索引/写索引`、`表格.读快照`、`表格文字.表格转文字`、`看表规范.分科目规范/分表规范/精读规范`、`金标准.建索引/科目清单/表清单/候选槽位/编号存在`
- Produces:
  - `第一遍材料(文件文字: str, 科目名们: list[str]) -> tuple[str, str]`
  - `第二遍材料(文件文字: str, 科目划分: list, 表名册: dict[str, list[str]]) -> tuple[str, str]`
  - `第三遍材料(表文字: str, 科目: str, 表名: str, 候选: list[dict]) -> tuple[str, str]`
  - `识别一侧(配置: dict, 表文件路径: str, 侧名: "A"|"B", 运行目录: Path, 金标准主文件: Path, 取消=None) -> dict`：返回 `{"结构清单": Path, "合集": Path, "统计": {...}}`
  - `铺格子(结构记录: dict) -> list[dict]`：只生成身份，原值留空
  - `补原值(记录们: list[dict], 快照: dict) -> list[dict]`：程序读原文件填 `原值/原值状态`

**第一遍：分科目**

- 材料：整个文件的表格文字 ＋ 103 个科目名清单 ＋ `分科目规范()` ＋ 输出格式要求 ＋ 一条示例（用假名字，别用真实科目）
- 输出（一个 JSON 对象，一段不漏）：
  ```json
  {"划分":[{"行范围":[2,20],"科目":"货币资金"},{"行范围":[21,31],"科目":"非表格"}]}
  ```
- 规则：每个行范围必须落在科目名清单里，或者是 `"非表格"`（说明段、目录、纯文字）。行范围要覆盖文件全部有内容的行，不得留空档。
- 校验：任一 `科目` 不在清单里且不是 `"非表格"` → 这一遍判失败，重跑这一遍。

**第二遍：分表**

- 材料：整个文件的表格文字 ＋ 第一遍的划分结果 ＋ **只给第一遍出现过的那些科目的表名清单** ＋ `分表规范()` ＋ 输出格式
- 输出：
  ```json
  {"表":[{"行范围":[2,9],"科目":"货币资金","表名":"余额构成"}]}
  ```
- 规则：`表名` 必须是该科目表名清单里的原值；`行范围` 不得跨出第一遍该科目的行范围。
- 校验：表名不在清单里 → 判失败，重跑这一遍。

**第三遍：精读每张表**

- 材料：**只这一张表**的文字 ＋ 科目 ＋ 表名 ＋ 该表的候选槽位（`候选槽位()` 输出，只带编号／槽位名／行路径／列路径／别名）＋ `精读规范()` ＋ 输出格式
- 输出（一个 JSON 对象）：
  ```json
  {
    "列":[{"列":"B","路径":"项目","角色":"行名列","期间":null},
          {"列":"C","路径":"期末余额","角色":"数据列","期间":"期末"},
          {"列":"D","路径":"期初余额","角色":"数据列","期间":"期初"}],
    "行":[{"行":56,"名字":"项目","角色":"表头"},
          {"行":57,"名字":"库存现金","角色":"数据","槽位":{"C":"C-N006-T001-S002","D":"C-N006-T001-S003"}},
          {"行":60,"名字":"合计","角色":"合计","槽位":{"C":"C-N006-T001-S009","D":"C-N006-T001-S010"}}],
    "作用范围":{"币种":"人民币","单位":"元"},
    "例外":[]
  }
  ```
- 要点：
  - `路径` 和 `名字` 多级时用斜杠连接（如 `期末余额/账面余额`），**不许为了整齐拍平**。
  - 每个数据行的 `槽位` 是"列字母 → 金标准编号"的映射，必须逐行给全。
  - 结构描述可以按 SKILL 的降级规则给代表行，但**槽位映射不能降级**——它是交付物，少一格就是少一格。
  - `例外` 里要写清行列不齐、右侧并表、跨行合并分组等情况怎么处理。
- 校验：`槽位` 里任一编号用 `编号存在()` 查不到 → 该格留空，最终记为"槽位编号缺失"，**不许程序猜或模糊匹配**。

**铺格子的规则（程序机械执行，不判断语义）：**

1. 遍历 `行` 中角色为 `数据`／`小计`／`合计` 的行，与 `列` 中角色为 `数据列` 的列两两交叉。
2. 每格生成一条记录：`科目`、`表名` 取结构记录；`行路径`＝该行名字按斜杠拆开；`列路径`＝该列路径按斜杠拆开；`期间角色`＝该列期间；`币种/单位`＝作用范围；`槽位`＝该行 `槽位` 映射里对应列字母的值（缺失则留空）。
3. 角色为 `表头`／`标题`／`说明`／`注释`／`空行` 的行**不出数据格身份**。
4. 角色为 `行名列` 的列**不参与数据格交叉**。
5. `例外` 点名的位置按例外说明单独处理，优先级高于上述规则。
6. 坐标按 `工作表名!列字母+行号` 生成。

**材料三段（每份材料都遵守）：**

| 段 | 内容 |
|---|---|
| 一 | 表格文字（`表格转文字` 产物，带坐标和合并标注）——**不裁剪** |
| 二 | 该遍需要的前序结论（第一遍无；第二遍带科目划分；第三遍带科目、表名、表前说明） |
| 三 | 该遍的看表规范 ＋ 输出格式要求 ＋ 一条示例（只给形状，不给答案） |

**禁止事项（每一遍都适用）：**
- **不得把金标准条目放进第一、二遍材料。** 第三遍只给该表候选槽位，不给全库、不给其他表的候选。
- 不得用关键词从全库挑条目——那要求程序先读懂表，等于两步识别，逻辑上自相矛盾。
- 不得裁剪材料：表头、表前说明、合并标注、单位口径句都要在。
- 不得并发调用模型。

**断点续跑：** 接续索引按 `识别A:科目`／`识别A:表` 登记（B 侧同理）；已登记的直接跳过。重做某张表时，新结果必须覆盖旧文件，**不允许两套并存**。

**文件规模说明：** 两份真实文件都在一次上下文内——A 侧约 2 万字符，B 侧约 6 万字符。若将来文件更大，按行分窗并保留约 10% 重叠，跨窗处结论不一致的段落交人工。

### Task 9: 比对引擎（按金标准槽位编号配对）

**为什么要重写这一节：** 原设计是"A 和 B 的身份键（槽位＋期间角色＋选取范围＋币种）相同就对应"。可 A 是 Word 排版稿、B 是 Excel 数据源，同一含义两边写法天生不同：

- A 写 `预付款项-账龄 / 1年以内（含1年） / 期末余额 / 账面余额 / 金额`
- B 写 `预付款项按账龄列示 / 1年以内 / 期末余额 / 账面余额 / 金额`

逐字比必然对不上。实测 6151 格里 5706 格死在"身份证不同"上，只对上 14 格。

**新做法：金标准当唯一公共语言。** A 的每一格挂到金标准的某个槽位编号，B 的每一格也挂到金标准的某个槽位编号；**挂到同一个编号的才算对应**。写法差异在第三遍挂编号时就由模型吸收了，比对这一步只认编号，不再碰任何文字。

**Files:**
- Create: `核心/比对.py`、`测试/test_比对.py`（重写）

**Interfaces:**
- Produces: `建立对应(A合集: list[dict], B合集: list[dict]) -> list[对应项]`
- **配对键只有一个：`槽位`**（金标准槽位编号）。原 `排除比较维度` 参数整个删除——不再有任何按维度比对的逻辑。
- 判定规则：
  | 情况 | 结果 |
  |---|---|
  | A 恰 1 格、B 恰 1 格 | 对应 |
  | B 侧没有该编号 | 未对应，原因"仅A侧有" |
  | A 侧没有该编号 | 未对应，原因"仅B侧有" |
  | A 侧 ≥2 格 | 未对应，原因"A侧重复" |
  | B 侧 ≥2 格 | 未对应，原因"B侧重复" |
  | 编号为空或格式不合 `C-N` 开头 | 未对应，原因"槽位编号缺失" |
- 金额不参与配对。**未对应格也必须逐条进清单**，不能丢。

### Task 12: 结构维护（人工增删行 → 桥接操作记录；先定位命名区域再算相对行号）

**为什么要重写这一节：** 原实现按 `{工作表: range_name}` 一对一取命名区域，再用"整张工作表的第 N 行"减"该区域首行"当相对位置。可 A 侧的 `表A.xlsx` 里，`sheet1` 一张工作表装了 **66 张表**（TA_001…TA_066）。把整张工作表当成一张表，位置必然算错。

实测：删除第 463 行，算出的 `index` 是 461，可它指向的 TA_001 只有 3 行（B2:D4），桥接报"行列变更位置、数量或样式来源越界"。

**这不是桥接不支持增删行。** 桥接接口写明支持 `axis: row|column` ＋ `action: insert|delete`，`index` 是**相对于该命名区域**的第 0 个起始位置。是我们把相对基准搞错了。

**改成：先定位变更落在哪个命名区域，再算该区域内的相对位置。**

**Files:**
- Create: `核心/结构维护.py`、`测试/test_结构维护.py`（重写定位逻辑）

**Interfaces:**
- Consumes: `核心.表格.读快照`（`snapshot["names"]` 里有每个命名区域的 `sheet` 与 `range`）
- Produces:
  - `区域归属(快照, 工作表: str, 起始行: int, 行数: int) -> str | None`：返回完整覆盖该行段的命名区域名；找不到返回 `None`
  - `生成结构操作(基准表A路径: Path, 修改后excel路径: Path) -> list`：**去掉 `位置关联` 参数**，直接返回 operations 数组
- operations 元素按桥接接口：`{"range_name","axis":"row|column","action":"insert|delete","index","count","template_index"}`；`index` **相对命名区域首行**，不是相对工作表。
- 判定规则：

  | 情况 | 处理 |
  |---|---|
  | 结构未变（行签名、合并集都相同） | 返回 `[]`，直接回写保存内容。**不要求名称相同**——人工只改公司名属正常修改 |
  | 合并集变化 | `raise`，交人工（合并结构改动不猜） |
  | 变更行段完整落在某个命名区域内 | 生成操作，`index = 段首行 − 该区域首行` |
  | 变更行段跨两个命名区域 | `raise`，交人工 |
  | 变更行段落在所有命名区域之外 | `raise`，交人工 |
  | 同时存在增行与删行 / 多处互不相连的增或删 | `raise`，交人工 |
  | 列结构变化 | `raise`，交人工（本期不做） |
- **桥接自身的合并限制照旧**：切入横向或纵向合并块、复制跨合并的样式来源、整行纵向续接时，桥接会拒绝并说明原因——如实报出去交人工，不绕过、不硬改。
- **测试从实际修改并保存的 Excel 出发**，不手填操作数组冒充。
